# 状态存储跨进程互斥

## 问题与边界

原 Store 只有实例内互斥，独立 Gateway/CLI 对同一个 state.json 执行读取-修改-保存时可能丢失更新，甚至使已经改变的 Writer 状态被旧快照覆盖。这是一个已确认的并发缺陷，不代表已经复现或定位了所有线上锁异常。

## 实现

- Windows 使用 LockFileEx，Linux/macOS 使用 flock；所有 Load/Update 使用独占的稳定 state.json.lock 文件锁。Update 在同一持锁区间内读取最新状态、执行回调并替换状态文件。
- sidecar 不删除，避免两个进程锁住不同文件对象；关闭描述符或进程退出后由操作系统释放。文件存在不代表有活动锁。
- 竞争文件锁最长等待 20 秒，失败返回错误；不抢占其他进程。实例内互斥仍由原 mutex 处理。
- 现有路径在 Store 初始化时解析为绝对路径并解析已有符号链接；不支持运行期间替换锁文件、不同硬链接别名或不遵守锁协议的直接写入。
- 保存使用同目录唯一临时文件、Sync、关闭再 Rename，失败清理临时文件。所有遵守锁协议的读取者均不会读到写入中的状态。未承诺 Windows Rename 的跨应用原子可见性、断电后目录元数据耐久性或网络文件系统锁语义。
- 不修改 Writer 续期、权限、Process 生命周期。该文件锁是内部状态事务互斥，不是项目 Writer。
- 必须确保访问同一状态路径的 Gateway/CLI 都升级到遵循同一协议的版本；旧版本及手动编辑不受该互斥约束。部署时应先停止旧实例，不混用新旧二进制。

## 验收

EADM Windows：8 个独立 Store 对象共 96 次更新，3 个独立子进程共 36 次更新；锁竞争超时、事务回滚、进程退出不残留锁、旧状态规范化通过。Environment 两个独立 Service 竞争重叠根目录 Writer，仅一个成功；管理员接管后旧凭证不能续期/释放，其他资源更新不丢失。Store、Environment、Memory、Workspace、Catalog、Verifier 全包测试及 Gateway/App/CLI/Desktop 相关专项通过。

DADM Linux：从独立测试 Worktree 复制本阶段 Store 与相关 Model 文件，运行 Store 全包测试通过（含多进程竞争及退出释放）。测试工作树内容已恢复干净，Writer 已释放；临时环境尚未到期，正常保留至 TTL。未修改源 checkout。macOS 尚未实测。

本轮发现既有索引后台任务测试重启任务后未等待结束即清理临时目录；测试补上等待，重复五次及相关专项复跑通过。未修改索引实际业务逻辑。

## 未解决

状态文件互斥不等于实际项目文件写入互斥。旧 Exec/Run/Verifier 在 Writer 被接管后可能存在短暂退出窗口；下一阶段应为 ADM 管理的写入操作设计交接屏障，并明确与独立常驻 Process 的边界。尚未执行整个项目全量回归、跨系统安装验收或发布。
