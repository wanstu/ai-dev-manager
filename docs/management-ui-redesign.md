# ADM 管理端整体重设计

## 目标
Desktop 与 Web 共用同一套功能、页面结构、设计令牌及状态语义。保留现有业务与权限边界，不为视觉重构删除现有操作。现代、紧凑、低认知负担；默认页面优先展示当前任务，而不是底层实现术语。

## 生命周期
常驻进程 Process 是 ADM Gateway 的运行资源，以 process ID、Environment、PID、命令、目录、启动时间、状态、日志和监听端口进行管理。进程运行、会话退出、Writer 释放/到期、管理员接管之间没有生命周期绑定。管理员直接启动、查看、停止，无须获取 Writer。Agent 的启动/停止仍需原有授权检查；这不会让进程持有或续期 Writer。执行任务 Run 和 Verifier 是有时限的项目操作，保留授权失效检查，不得自动续租。Gateway 正常关闭时清理其管理的子进程；异常退出、跨 Gateway 进程可见性和子进程树回收仍需验收。任意 OS PID 不得作为 ADM 进程 ID 使用。

| 工作区 | 登记目录、搜索排序、发现项目、创建环境、继承选择、移除 | 主操作突出，列表显示路径与环境数，发现结果可批量操作 |

| 进程与任务 | Writer、Verifier、Process、Run、状态与日志 | 常驻进程与锁分区；无环境时查看全局进程；命令、PID、目录、状态、日志；管理员无锁停止 |
| MCP 工具 | 定义、导入导出、健康检查、密钥引用、继承及批量分配 | 工具列表/连接状态/配置分层，批量操作保持作用域清楚 |
| 技能 | 技能、来源、扫描、可用性、默认启用、批量分配 | 技能库与来源分离，状态可筛选，危险清理明确确认 |
| 记忆 | 全局、环境级键值、增删改查 | 明确作用域、搜索与可读内容、保留人工加载行为 |
| 连接与服务 | Profile、连接状态、端点、诊断、启停、远程访问、Admin/Agent Key | 连接和生命周期优先，访问控制单独分组，密钥不回显 |

## Memory 行为契约

- 当前 Memory 是持久化 KV 存储，不是自动总结型/向量检索型记忆。
- 全局记忆跨 Workspace / Environment 共享；Agent 可显式读取，写入和删除仅 Admin 可执行。
- Environment-private Memory 只属于一个明确的 Environment；Agent 的读取/写入/删除请求必须带该 Environment ID。
- Desktop 进入 Memory 页面时自动加载 Global Memory 供管理员查看；Environment-private Memory 必须显式加载。切换连接或 Environment 时清空对应的已显示值，防止串用。
- Agent 通过 adm_memory 的 global_list/global_read 与 environment_list/environment_read 显式召回。Gateway instructions 要求在用户任务确实依赖历史决策时才读取，并禁止读取其他 Environment 的私有记忆。
- 不自动注入全部记忆、不自动总结、不自动保存或删除。environment_context_bundle 只暴露 private-memory 数量，不暴露内容；普通 snapshot / inspect 也不包含记忆值。
- UI 支持搜索、长文本/多行内容、编辑（保持 key 不变）、删除确认；值为空字符串仍然合法。

## 分期
1. 公共视觉与导航：统一主题令牌、字体、表单、按钮、空状态、状态标签、响应式布局、紧凑的管理范围、统一弹窗；不改现有权限。
2. 进程页：独立进程管理，跨环境列表、日志、无锁管理员停止；新增回归测试。
3. 逐页功能重排：工作区/开发环境、MCP/技能/记忆、连接/权限/诊断/设置/关于；逐项检查操作是否保留、是否更易理解。
4. 跨平台验收：Desktop/Web 共用页面，Windows/Linux、窄窗口、明暗/渐变主题、键盘、滚动和弹窗；Linux DEB 构建、安装、升级和卸载。

不以 CSS 修改等同于全页面验收，不以单个截图代替功能回归。
