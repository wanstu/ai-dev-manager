# ADM v1.4.3

让所有由 ADM 管理入口创建的 Git worktree 都使用临时生命周期。

- `environment_worktree_create`（管理员创建）现在也产生具有 30 天 TTL 的临时 Env，不再创建永久 worktree。
- `environment_temporary_promote` 和 `resource_retention_promote` 均拒绝将受管理的 worktree Env 提升为持久化；普通 Env 的管理员提升不受影响。
- 提供 Admin-only `environment_worktree_migrate_temporary`（`execute=false` 预览，`true` 执行）及 Desktop/Web 管理页“迁移持久化 Worktree”按钮。
- 历史迁移一次性把旧持久化 managed worktree 标记为临时，给予从迁移时算起的 **30 天宽限期**；不会删除工作目录、文件、Git 分支、Env ID 或 Workspace，也不会自动执行迁移。
- 在 30 天后仍使用 v1.4.2 的运行时状态、Writer、Git dirty、ignored files、未发布提交和远程验证安全限制执行过期清理。
- 其他普通（非 managed worktree）Env 和 Workspace 继续保持各自的持久化配置。
- 测试覆盖管理员与嵌套 worktree 新建、两种提升入口拒绝、历史迁移只改元数据、原地保留目录、幂等和 Agent/Admin 权限隔离。

管理员操作：升级 Desktop/Gateway 到 v1.4.3 后，进入 **Environments → 迁移持久化 Worktree**，核对预览数并确认执行一次。随后可查看所有 managed worktree 的临时到期信息。正式 CI 产物由 GitHub Actions 构建、测试和发布。
