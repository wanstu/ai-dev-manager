# Release Hotfix — ADM v1.0.1

Date: 2026-09-11
Status: release hotfix prepared after v1.0.0 CI failure

## Reason

The `v1.0.0` tag was pushed and correctly triggered the GitHub Actions release workflow, but the Windows `go test -count=1 ./...` job failed inside `TestVerifierRealHTTPAcceptanceNonGitRepositoryCopy`.

The failing nested verifier run reported:

```text
--- FAIL: TestRuntimeOwnerRealHTTPRestartReconciliation
mcp_acceptance_test.go:638: check Gateway http://127.0.0.1:<port>: Get "http://127.0.0.1:<port>/healthz": read tcp ... wsarecv: An existing connection was forcibly closed by the remote host.
```

## Diagnosis

This was not the earlier `pjadm.exec` outer timeout problem. The earlier timeout problem was mitigated by using async `run_start`/`run_status` and was verified live.

The CI failure was a Windows shutdown-race classifier issue:

- `StopHTTP` requests graceful Gateway shutdown.
- During shutdown, a follow-up `/healthz` probe can race with the server closing its socket.
- Windows can surface that as `wsarecv: An existing connection was forcibly closed by the remote host`.
- ADM should classify that probe failure the same way it treats connection refused / actively refused while checking whether a Gateway is stopped.
- Protocol problems and incompatible health responses must still remain errors.

## Fix

Commit:

```text
b73b749 fix(gateway): tolerate shutdown connection reset
```

Implementation:

- `isHTTPConnectionFailure` now treats shutdown-race connection reset / forcibly-closed errors as stopped-endpoint observations.
- Added `TestHTTPConnectionFailuresIncludeShutdownRaces` so this Windows failure mode remains covered.
- No command authority, runtime owner, MCP, verifier, workspace, Environment or cleanup semantics changed.
