# Phase 02 — Structured Verifier Runtime · Plan 02-01

## Objective

Make structured verification a first-class, Environment-scoped, Agent-visible capability on a non-Git Environment: persist verifier definitions on `Environment`, run them through the existing allowlisted `Runtime.Exec` while the writer lease is held, and return typed pass/fail/timeout results over the ADM Gateway. Prove the product capability with V2's own `go test ./...` through a real Streamable HTTP MCP client on a non-Git root.

This is one tracer-first plan. Do not split unless implementation reveals a blocking contradiction.

## Tasks

### Task 1 — Tracer: Environment verifier model, core result mapping, first runnable verifier path

1. In `internal/model/types.go` add Environment-scoped `VerifierDefinition` with stable ID plus:
   - `kind` (`test|lint|build|custom`)
   - `enabled`
   - `executable`
   - `args`
   - `cwd`
   - `timeout_seconds`
   - optional human `name`
   Add `Verifiers []VerifierDefinition` to `model.Environment`; do not add a global verifier catalog to `model.State`.
2. Add `internal/verifier/service.go` owning:
   - Environment-scoped definition lookup/list/add/remove over `store.Store`;
   - stable verifier IDs via `identity.New("vf")`;
   - ephemeral `Result` containing verifier ID, kind, status, exit code, duration, timed_out, summary, stdout, stderr;
   - pure classification of Runtime outcomes into `passed`, `failed`, or local execution/policy error.
3. In `internal/app/service.go` wire the verifier service and add `RunVerifier(ctx, environmentID, writerOwner, verifierID, maxOutputBytes)`:
   - resolve Environment and enabled definition;
   - fail missing/disabled verifier locally before execution;
   - require the matching writer;
   - create the Environment Runtime through existing `Service.Runtime`;
   - apply verifier timeout through an app-owned deadline context;
   - reuse the existing Exec writer-heartbeat/cancel pattern;
   - call `Runtime.Exec` with definition executable/args/cwd and output bound;
   - derive `timed_out` from the verifier deadline context, not error text;
   - measure duration and classify the result;
   - keep generic `Runtime.Exec` / `CommandResult` unchanged unless a test proves this impossible.
4. Add focused tests using the existing helper-process pattern for exit 0, nonzero exit, timeout and start/policy error.

Nyquist coverage: **V-U1, V-U2, V-U3, V-U5** plus the first positive execution seam.

### Task 2 — Environment-scoped definition CRUD and minimal human declaration path

1. Add app methods for verifier definition list/add/remove, delegating to `internal/verifier`.
2. Validate definition shape at the verifier boundary:
   - kind is one of `test|lint|build|custom`;
   - executable is nonblank;
   - timeout is nonnegative;
   - empty cwd means Environment root;
   - definition creation does not inspect Git and does not grant executable authority.
3. Add minimal CLI management under `environment verifier`:
   - `add --environment-id ... --name ... --kind ... --executable ... [args/cwd/timeout/enabled]`
   - `list --environment-id ...`
   - `remove --environment-id ... --verifier-id ...`
   Keep Desktop frozen.
4. Add persistence tests:
   - definitions survive a fresh `app.New(statePath)` reload;
   - two Environments do not share definitions;
   - zero-config Environment reloads cleanly with no phantom verifier;
   - removing a missing verifier fails clearly.

Nyquist coverage: **V-I1** and VERIFY-02 declaration semantics.

### Task 3 — Agent Gateway: `environment_verifier_list` and `environment_verifier_run`

1. In `internal/gateway/server.go` add only the locked Agent-facing tools:
   - `environment_verifier_list {environment_id}` → Environment-scoped verifier definitions, no writer required;
   - `environment_verifier_run {environment_id, writer_owner, verifier_id, max_output_bytes?}` → structured verifier result, writer required.
2. Keep handlers thin and use existing `toolResult`; do not create a new transport or per-Environment server.
3. Add Gateway integration tests proving:
   - list is Environment-scoped and writer-free;
   - run requires matching `writer_owner`;
   - missing/disabled verifier fails locally;
   - a broken verifier does not break unrelated tools such as `gateway_info` and `read`.

Nyquist coverage: **V-I2, V-I3, V-I6** and VERIFY-03 Gateway availability.

### Task 4 — Required negative acceptance, timeout/failure identity and bounded output

Add focused app/verifier/Gateway tests covering all remaining policy requirements:

1. **V-U4:** chatty verifier output remains bounded in the returned structured result and does not become a transport failure.
2. **V-U6:** missing/disabled verifier ID returns a clean local error.
3. **V-I4:** verifier cwd root/subdirectory succeeds; `..`, absolute outside-root and symlink-outside-root escape are rejected by existing Runtime containment.
4. **V-I5:** a stored verifier whose executable is absent from the global allowlist fails at run time; definition existence never grants execution authority.
5. **V-I7 / VERIFY-01 / VERIFY-04:** with zero configured verifiers, normal Environment/file/runtime development still works. At minimum preserve tree/read/write/edit/exec coverage and an empty verifier list.
6. Structured result semantics:
   - exit 0 → `passed`, exit code 0, `timed_out:false`;
   - nonzero exit → `failed`, real exit code, `timed_out:false`;
   - deadline → `failed`, `timed_out:true`, measured duration, never a hang or false pass;
   - start/policy failures remain local tool errors, distinct from completed verifier failures.
7. Verify a long verifier keeps the writer lease alive via the reused heartbeat semantics.

Nyquist coverage: **V-U1..V-U6 and V-I3..V-I7**.

### Task 5 — Mandatory real Streamable HTTP acceptance on a non-Git V2 copy

In dedicated `internal/gateway/verifier_acceptance_test.go`, place **V-R1, V-R2, and V-R3 only**, using the existing `httptest.NewServer(NewHTTPHandler(service))` + `mcp.StreamableClientTransport` pattern. Keep these real acceptance cases out of `server_test.go` so the non-Git repository copy can explicitly exclude the self-recursive acceptance file.

1. Create a temporary copy of this repository suitable for `go test ./...`, excluding `.git`, `.planning`, generated binaries/build output, caches, and `internal/gateway/verifier_acceptance_test.go`; assert the copied root is non-Git **and assert the copied tree does not contain `verifier_acceptance_test.go`** before invoking the inner suite.
2. Explicitly allowlist `go`.
3. Register Workspace + Environment rooted at the non-Git copy.
4. Add an enabled `test` verifier for `go test ./...` with a bounded, realistic timeout.
5. Acquire the Environment writer.
6. Through a real Streamable HTTP MCP client call `environment_verifier_run` and assert:
   - verifier identity is present;
   - status is `passed`;
   - exit code is 0;
   - output is bounded.
7. Over the same real HTTP boundary also prove:
   - a trivial configured non-Git verifier passes (**V-R1**);
   - V2's own inner `go test ./...` passes through the verifier without recursively re-entering this acceptance test (**V-R2**);
   - a deliberate nonzero verifier returns structured bounded failure;
   - a deliberate timeout returns structured bounded failure with `timed_out:true` and is distinct from nonzero exit (**V-R3**).

Nyquist coverage: **V-R1, V-R2, V-R3** and all four ROADMAP Phase 2 success criteria.

## Required Negative Acceptance Tests

- Non-Git Environment can run a configured verifier; Git is not a prerequisite.
- Zero verifier config still permits normal development.
- Missing/disabled verifier fails locally without damaging unrelated Gateway tools.
- Definition without allowlisted executable cannot run.
- cwd escape, including symlink escape, is rejected.
- verifier run without the matching writer is rejected.
