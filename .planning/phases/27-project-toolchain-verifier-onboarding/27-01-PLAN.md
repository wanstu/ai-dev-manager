# Phase 27 Plan — Project Toolchain & Verifier Onboarding

## Objective

Close the real external-Agent verification gap found in Phase 26: after a human authorizes the project toolchain, `@pjadm` must be able to run the project's Go verifier inside the isolated Environment without falling back to CodexPro.

## Tasks

### 1. Extend human `workspace prepare`

Add optional explicit Go preparation:

```text
workspace prepare <workspace-id> --go <absolute-go-executable>
```

Rules:

- existing `workspace prepare <id>` behavior remains an explicit minimum `standard + git` authorization;
- `--go` must be explicit and absolute;
- machine-local execution authorization is persisted on the user-level Workspace record, not Project config;
- local minimum `standard` may upgrade a weaker Project mode but must not downgrade `full`;
- add `go` to the Workspace-local `AllowedExecutables` idempotently;
- set Workspace-local `ToolPaths["go"]` to the explicit path;
- preserve existing Project policy/MCP/Skill/verifier content;
- add a conventional Project `go-test` verifier only when that verifier ID is absent;
- never overwrite an existing `go-test` verifier silently;
- explicit caller Runtime Override policy remains higher precedence than the Workspace-local overlay.

### 2. Verify configuration resolution

Tests must prove:

- an unprepared Workspace still resolves read-only;
- plain prepare enables managed Git worktree but not Go;
- Go prepare exposes verifier capability and the configured Go ToolPath;
- repeated prepare is idempotent;
- unrelated existing verifier/MCP/Skill/ToolPath config survives.

### 3. Real external-Agent verifier acceptance

Use the existing Phase 26 Environment. After the human/control-plane toolchain authorization is applied to the base Workspace, use `@pjadm` only for the Environment operations:

```text
run_verifier(id=go-test)
run_verifiers(ids=[go-test])
```

The Agent must not supply raw worktree paths or raw shell strings.

### 4. Investigate advertised-but-failing search

Reproduce the routed `search` failure after toolchain preparation. If it is a concrete implementation/config bug, fix it with a focused regression test. If it is input/limit behavior, improve the structured error so the Agent can diagnose it. Do not add a speculative generic health subsystem.

### 5. Verification

Inside the Environment, after Go has been human-authorized:

```text
go fmt ./...
go test ./...
go test -race ./internal/environment ./internal/gateway ./internal/adapter/mcpgateway ./internal/daemon
go vet ./...
go build -o ai-dev-manager-v0.7-review.exe ./cmd/ai-dev-manager
```

Also run the real `go-test` verifier through `@pjadm`.

If Gateway/network behavior is unchanged, no additional fixed-path network acceptance is required solely for this phase.

## Exit criteria

- `workspace prepare --go` is explicit, minimal, config-preserving and idempotent.
- default Workspace registration remains read-only.
- the real Phase 26 Environment can run `go-test` through `@pjadm` and return structured verifier output.
- any observed search/capability inconsistency is fixed or precisely diagnosed.
- full test/race/vet/build gate passes.
