# Phase 16 Plan 16-01 — Deterministic Verify Workflow

## Objective

在 Phase 15 daemon-owned Run lifecycle 上增加一个显式 `verify` workflow，并通过真正的 Planner → Executor → Reviewer 数据流验证 orchestration contract。

## Implementation Steps

1. 扩展 `internal/agent` lifecycle model：
   - Manager 支持 executor registry + default executor。
   - Start 支持显式 executor/workflow selection。
   - RunStatus 新增可选 workflow/stage/plan/steps/review。
   - 保持 Phase 15 `lifecycle` 默认兼容。

2. 新增 workflow contracts / verify implementation：
   - Planner / Plan / PlanStep。
   - StepExecutor / StepResult。
   - Reviewer / ReviewResult。
   - RuntimeBuilder abstraction 返回 `runtimeadapter.Runtime`。
   - VerifyPlanner 根据 capabilities 生成 `git.status -> git.diff -> verify.run_many`。
   - RuntimeStepExecutor 顺序调用 `Runtime.Invoke`。
   - VerifyReviewer 根据 verifier structured results 得出 pass/fail。

3. 把 workflow updates 写入 RunStatus：
   - planning / executing / reviewing / completed stage。
   - plan/steps/review 可被并发 status 安全读取。
   - cancellation 优先于 late executor completion，不能把 cancelled 覆盖回 completed/error。

4. daemon wiring：
   - `lifecycle` + `verify` executors 注册到同一 Agent Manager。
   - verify runtime factory 复用 daemon-owned `controlplane.Service.BuildRuntime`。
   - Agent Control API `POST /agent/run` 接收可选 `executor`。

5. CLI：
   - `agent run --workflow verify [path|workspace-id]`。
   - 默认无 flag 仍选择 lifecycle。
   - human output 显示 workflow stage/review；JSON 保留完整结构。

6. Tests / acceptance：
   - manager executor selection / unknown executor / lifecycle compatibility。
   - verify workflow pass/fail/capability error/cancel。
   - CLI process-level acceptance：另一个 invocation status 到 completed + review decision。

7. 验证后更新 README / PROJECT / ROADMAP / STATE。

## Verification

Targeted:

```text
go test ./internal/agent ./internal/daemon ./cmd/ai-dev-manager
```

Full gate:

```text
go fmt ./...
go test ./...
go vet ./...
go build -o ai-dev-manager-phase16.exe ./cmd/ai-dev-manager
```

Real binary acceptance uses an isolated config root/workspace with an explicit verifier so it does not alter the user's existing daemon/runtime state.

## Exit Decision

Phase 16 completes only if the `verify` workflow leaves auditable plan/steps/review state and the same Run is observable across independent CLI invocations. A reviewer `fail` must remain a completed orchestration with `review.decision=fail`; infrastructure/planning/runtime errors use Run state `error`.
