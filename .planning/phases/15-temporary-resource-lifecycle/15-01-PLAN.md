# 15-01 Plan — Temporary Env/MCP/Skill Resource Lifecycle

## Goal

Define and implement safe lifecycle metadata and cleanup surfaces for temporary resources created through Gateway/MCP-oriented workflows without changing the durable-by-default behavior of CLI/UI-created resources.

## Requirements

- Add explicit persistence metadata such as `durable` vs `temporary`.
- Track creator surface, owner/session identity, created_at, last_used_at, optional expires_at and retention policy.
- Support attachment semantics: a temporary MCP/Skill/provider resource may be attached to one Environment and cleaned with it when safe.
- Provide cleanup inspection/dry-run before destructive cleanup.
- Refuse cleanup when there is an active writer, active process/run, dirty/unpublished managed worktree, unknown ownership, or insufficient evidence.
- Preserve existing Environment/workspace deletion safety.
- Do not clean CLI/UI-created resources unless explicitly marked temporary.

## Candidate surfaces

- `resource_retention_inspect` / `temporary_resource_list`
- `resource_retention_cleanup --dry-run`
- `resource_retention_cleanup --execute`
- promote temporary to durable
- mark durable as temporary only with explicit user action
- Desktop views over the same Core state in Phase 16

## Non-goals

- No automatic cleanup without policy and preview.
- No task/session orchestration.
- No silent project directory deletion.
- No cleanup of unmanaged host files.
- No Desktop-only retention behavior.

## Validation

- temporary and durable resources are distinguishable in state and diagnostics;
- cleanup preview explains why each resource is eligible or skipped;
- active writer/process/run blocks cleanup;
- managed worktree dirty/unpublished checks are honored;
- CLI/UI-created resources remain durable by default;
- Gateway/MCP-created temporary resources are removable only through safe Core cleanup paths;
- full `go test -count=1 ./...`, `go vet ./...`, and `git diff --check` pass.
