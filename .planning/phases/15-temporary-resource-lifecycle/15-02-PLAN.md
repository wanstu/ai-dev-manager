# 15-02 Plan — Temporary Environment Cleanup and Bounded Inspection

## Goal

Close the remaining Phase 15 lifecycle gap for temporary Environments while fixing the dogfood blocker where Environment inspection can return unbounded disabled catalog facts.

## Requirements

- Ordinary temporary Environments may be removed by explicit cleanup only as ADM state records; Workspace state, project directories and host files are never deleted.
- Gateway-owner cleanup may destroy ADM-managed worktree Environments only through the existing managed worktree destroy safety path, with dirty, unpublished, runtime, writer and ownership blockers honored.
- Cleanup eligibility must require temporary persistence, explicit owner evidence, expiry due, ready Environment state and Gateway-owner runtime evidence.
- Application-only cleanup remains conservative where runtime-owner evidence is unavailable.
- Environment capability reporting stays bounded: report catalog summary facts plus selected MCP/Skill detail facts, not every unselected disabled catalog entry.
- Dry-run and inspection surfaces must explain would-remove, skipped and blocker evidence before destructive execution.

## Non-goals

- No automatic GC or background cleanup.
- No deletion of ordinary project directories or unmanaged host files.
- No Desktop-only lifecycle behavior.
- No push, tag or release automation.
- No Phase 16 reopening.

## Validation

- Ordinary temporary Environment cleanup removes only the Environment state record and preserves Workspace state plus the underlying project directory.
- ADM-managed worktree cleanup destroys only an eligible temporary managed worktree through existing isolation destroy semantics and retains the managed branch.
- Dirty or unpublished managed worktrees remain blocked from retention cleanup.
- Bounded capability reporting suppresses unselected MCP/Skill detail facts while preserving catalog summary counts and selected-resource diagnostics.
- Focused app, Gateway, management and CLI tests pass.
- `go vet` and `git diff --check` pass; CRLF warnings may remain as existing Windows working-copy behavior.
