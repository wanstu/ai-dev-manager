# Plan 11-01 — Daemon-owned Workspace Runtime + MCP Lifecycle

## Objective

完成 daemon 生命周期内的 persistent Workspace runtime ownership：`runtime start/status/stop` 都通过 local Control API 操作 daemon 中同一个 Runtime Owner；CLI 退出后 Runtime MCP Host 与 configured MCP sessions 继续存在。

## Task 1 — Runtime Owner

Create focused runtime ownership logic under `internal/daemon` (or a tightly related package only if a concrete dependency requires it).

Model:

```text
RuntimeStatus
- workspace_id
- runtime_id
- desired_running
- state: starting/running/stopping/stopped/error
- mcp_host instance/endpoint
- configured_mcps activation statuses
- safe error
```

Implement:

- one active runtime entry per Workspace ID。
- `Start(ctx, workspaceID)`:
  - mark desired=true / observed=starting;
  - start daemon-owned MCP Host through the existing `controlplane.Service`;
  - activate configured MCPs through the same Service;
  - on success record running status;
  - on activation failure rollback configured MCP sessions + Host and record error, never fake running。
- idempotent start returns current running instance rather than starting a second Host。
- `Status/List` returns daemon observed state and refreshes configured MCP status from the retained Service/Activator where useful。
- `Stop(ctx, workspaceID)` closes configured MCP sessions and Host for only that Workspace, sets desired=false/stopped。
- `StopAll` for daemon shutdown。

No desired-state disk persistence in this task.

## Task 2 — Local Control API

Extend the Phase 10 loopback server with narrow runtime operations, for example:

```text
POST /runtime/start
GET  /runtime/status?workspace_id=<id>
POST /runtime/stop
GET  /runtime/list                 (optional but recommended for multi-workspace acceptance)
```

Requirements:

- JSON request/response only; bounded body; explicit method checks。
- Workspace ID required for start/status/stop。
- handlers call the single daemon Runtime Owner, not `controlplane.New()`。
- safe HTTP errors; no Env values/resolved EnvRefs in status。
- daemon stop first stops all owned runtimes, then final Control Plane `StopAll` cleanup。

## Task 3 — Daemon client + CLI runtime surface

Add daemon client helpers that first discover/probe the existing daemon and then call the validated loopback control endpoint.

CLI:

```text
ai-dev-manager runtime start  --workspace <id>
ai-dev-manager runtime status --workspace <id>
ai-dev-manager runtime stop   --workspace <id>
ai-dev-manager runtime list                 # if implemented
```

Rules:

- no local `BuildRuntime` fallback when daemon is absent; persistent command must fail clearly or report daemon-not-running。
- `--json` remains stable machine-readable output。
- existing `inspect`, foreground `serve`, and one-shot `mcp` commands stay compatible unless a minimal change is required by tests。

## Task 4 — Multi-process / Multi-workspace Acceptance

Use two temp Workspace directories registered under one temp config root.

Acceptance:

```text
start daemon
runtime start A
runtime start B

new CLI process:
runtime status A → running + endpoint A
runtime status B → running + endpoint B
endpoint A != endpoint B

connect official MCP client to A and B
A reads only A workspace
B reads only B workspace

runtime stop A
runtime status A → stopped
runtime status B → still running and connectable

stop daemon
→ remaining B host/session cleaned
```

Also verify repeat runtime start A is idempotent to the same Host instance/endpoint.

Where practical, configure a real local test MCP fixture for one Workspace and prove its activation status remains healthy across a separate CLI `runtime status` invocation, demonstrating retained daemon session ownership.
