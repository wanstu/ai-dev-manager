# 21-01 — Owner-local async verifier lifecycle

Planning commit: `2aceec3` on source baseline `5e3f67a`.
Requirements: ADM-GOAL-001/002, ADM-CORE-003/004/005/007/008/021, ADM-GW-001/003, ADM-NONGOAL-001, ADM-DEV-001/003.
New prerequisites: none.

## Objective

Add a real persistent-Gateway-owner asynchronous verifier-run lifecycle with stable `vfrun_` identity, bounded live output, terminal `verifier.Result`, matching-writer cancellation and no persisted/resurrected observations. Reuse existing verifier/Runtime authority instead of building a second execution policy.

Do **not** expose new MCP tools in 21-01; that is the 21-02 acceptance gate.

## Non-goals

- no generic `run_` replacement or alias;
- no CI/job graph/retry/orchestration semantics;
- no persistence/resume across Gateway restart;
- no Desktop/CLI feature work;
- no automatic conversion of blocking verifier calls;
- no Git/worktree/MCP/Skill prerequisites;
- no push/tag/release/subagents.

## Task 1 — Make verifier preparation reusable without changing sync semantics

Likely files: `internal/app/service.go`, optional new verifier execution helper file, focused app tests.

Create the narrowest reusable application seam needed by both blocking and owner-local verifier execution. Exact symbol names should be calibrated against the code during implementation, but the seam must provide one authoritative path for:

- Environment and verifier-definition lookup;
- enabled-definition validation;
- matching writer requirement;
- managed-root/runtime validation;
- executable allowlist + Environment-contained cwd;
- verifier definition snapshot and configured timeout;
- exec-denial recording source semantics;

Existing `Service.RunVerifier` must use the same seam so Phase 21 does not leave two divergent verifier policies. Preserve current successful blocking behavior and existing timeout result semantics in 21-01.

Acceptance V01:

- plain non-Git Environment verifier execution remains valid;
- no verifier configuration remains a local absence and does not affect files/Environment creation.

## Task 2 — Add owner-local `vfrun_` lifecycle

Likely files: `internal/gateway/runtime_owner.go`, new `internal/gateway/runtime_verifier.go`, `internal/gateway/runtime_run.go` only if extracting a shared bounded output buffer, focused owner tests.

Implement an owner-local verifier-run resource with:

- stable `vfrun_` ID;
- Environment ID, verifier ID/name/kind and launch writer owner;
- lifecycle state `running|succeeded|failed|canceled`;
- started/completed timestamps;
- bounded stdout/stderr snapshots and truncation flags while running;
- terminal retained `verifier.Result` when classification completes;
- structured `error_kind` / `message` for owner/runtime cancellation failures where appropriate.

Execution rules:

1. Start validates everything before installing the owner resource. A missing/disabled verifier, wrong writer, forbidden executable, escaped cwd or invalid managed root creates no `vfrun_`.
2. Start returns after the command has been prepared/installed and execution is owned by the Gateway, not by the caller context.
3. Execution uses the verifier-defined timeout, existing Runtime command policy and `verifier.Classify`.
4. Writer heartbeat runs while active. Heartbeat failure cancels the command tree and records `writer_heartbeat_failed`.
5. Explicit cancel requires the current matching writer plus the same writer owner recorded at launch.
6. List/status are read-only and Environment-scoped.
7. Environment drop cancels/removes affected verifier runs before metadata removal.
8. Owner close cancels active verifier runs and waits boundedly. New owner/restart begins empty.
9. No verifier-run field is added to persisted `model.State`.

Prefer extracting the already-proven `agentRunOutputBuffer` into a generic owner-local bounded output helper instead of duplicating buffering behavior. Generic Run tests must remain unchanged semantically.

Acceptance V02–V08:

- V02 real helper starts as `running`, emits early stdout, later becomes `succeeded` with `result.status=passed`;
- V03 non-zero verifier becomes lifecycle `failed` with classified failed result and retained bounded output;
- V04 verifier-defined timeout becomes lifecycle `failed`, `result.timed_out=true`, without being mislabeled as caller cancellation;
- V05 matching writer cancel reaches `canceled`; wrong/current-mismatched writer is rejected and does not cancel;
- V06 live stdout/stderr are bounded with explicit truncation evidence; a large-output helper does not grow unbounded memory;
- V07 writer heartbeat keeps a long verifier authorized; forced heartbeat failure cancels it with structured evidence;
- V08 owner close and Environment drop cancel active verifier runs; recreated owner has no old IDs and persisted state bytes contain no verifier-run observation.
