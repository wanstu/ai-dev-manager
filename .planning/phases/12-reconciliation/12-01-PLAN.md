# Plan 12-01 — Desired-state Persistence + Restart/Crash Reconciliation

## Objective

完成 v0.3 最终 vertical slice：`runtime start/stop` 改变持久化 desired state；daemon 每次启动都从该状态通过现有 RuntimeOwner 路径重建 observed Runtime/MCP；clean restart 与 crash restart 均不会复用旧 endpoint/session。

## Task 1 — Desired runtime store

在 `internal/daemon` 增加最小持久化：

```text
runtime/desired-runtimes.json
```

Schema v1：

```json
{
  "version": 1,
  "workspace_ids": ["ws_..."]
}
```

实现：

- load missing => empty desired set。
- deterministic sorted unique Workspace IDs。
- atomic write/replace，runtime directory app-owned。
- corrupt JSON / unsupported version => typed/clear error，不静默清空。
- add/remove helpers 在并发 RuntimeOwner 操作下保持一致。

Verification：round-trip、sorting/dedupe、remove、corrupt/version tests。

## Task 2 — RuntimeOwner desired/observed semantics

扩展 Phase 11 RuntimeOwner：

- owner 初始化时绑定 desired store。
- `Start`：验证 Workspace 后先 persist desired=true，再走现有 Host + configured MCP activation；失败时 desired=true 保留，observed=error。
- `Stop`：先 persist desired=false，再关闭 configured MCP + Host；失败时 desired 已明确为 false，observed=error 可诊断。
- daemon shutdown 使用一个 **observed-only stop path**，不得把 desired state 清掉。
- `Reconcile(ctx)`：load desired IDs，逐个复用 Start/reconcile 内部 observed-start 路径；单 Workspace 失败留下 error entry并继续其他 Workspace。
- Phase 11 API/状态结构保持兼容。

Verification：start persists、explicit stop removes、shutdown preserves、failed activation keeps desired、reconcile continues after one failure。

## Task 3 — Daemon startup reconciliation + stale owner recovery

修改 daemon Run/Start：

- daemon Run 构造 Control Plane + RuntimeOwner 后，在发布 healthy `daemon.json` 前完成 desired-state load/reconcile。
- individual runtime error 不终止 daemon；desired store本身损坏则 daemon startup fail。
- graceful daemon stop 调用 RuntimeOwner observed-only shutdown，然后 Control Plane StopAll。
- Start 遇到 fresh lease 但 health 不可达时，不再只等 readiness timeout；循环观察：
  - owner 变 healthy => 返回它；
  - lease 被释放 => 竞争启动；
  - heartbeat 超过 stale threshold => 清理旧 metadata/lease 并启动；
  - caller context/总体 bounded timeout => 返回明确错误。
- 保持同一 config root single healthy owner。

## Task 4 — Restart and crash acceptance

增加 process-level tests：

### Clean restart

```text
register A/B
start daemon
runtime start A
runtime start B
record daemon id/pid + endpoint A/B
stop daemon
start daemon
→ new daemon id/pid
runtime status A/B → running
→ endpoints are live and freshly rebuilt
runtime stop A
stop daemon
start daemon
→ A stopped, B running
```

### Crash restart

```text
start daemon
runtime start B
record old daemon pid + endpoint
kill daemon process directly (no /stop)
assert old endpoint unreachable
immediately start daemon
→ waits for/reclaims stale lease
→ new daemon id/pid
runtime status B → running with fresh live endpoint
```

Tests must clean up daemon even on failure。
