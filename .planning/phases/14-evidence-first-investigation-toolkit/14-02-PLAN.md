# 14-02 Plan — Optional Code Intelligence Provider + GitNexus Integration

## Goal

Add an evidence-provider layer that lets ADM combine its built-in static investigation helpers with optional external code intelligence providers such as GitNexus. The first target provider is GitNexus because it exposes graph-powered code intelligence through CLI/MCP surfaces and is designed around symbol, dependency, call-chain and impact evidence for AI agents.

The ADM product goal is not to own a full code-graph engine. ADM should detect, authorize, call and normalize optional external evidence into ADM's own investigation result schema while preserving clear provenance and fallback behavior.

## Product boundary

ADM owns:

- provider capability discovery and diagnostics;
- Environment-scoped authorization and root mapping;
- static fallback investigation when no provider is configured or healthy;
- normalization into ADM evidence/confidence/uncertainty models;
- provider provenance, freshness and failure explanation;
- optional MCP/CLI provider activation through existing MCP/runtime boundaries.

ADM does not own:

- reimplementing GitNexus internals;
- automatic repository indexing without explicit user/provider configuration;
- writing provider hooks into external agent configs without explicit import/preview/apply flow;
- treating GitNexus as a hard dependency;
- hiding provider uncertainty behind ADM confidence;
- orchestration, task planning or automatic fixes.

## Proposed architecture

Introduce a provider-neutral investigation path before adding more helpers:

1. Add an `InvestigationProvider` abstraction at the application layer.
2. Add a `code_intelligence_provider` capability fact family, e.g. `code_intelligence.gitnexus`.
3. Detect whether a provider is configured for an Environment using existing MCP/Skill/runtime configuration, but do not start/index/probe by default.
4. Allow Gateway-owner reports to include existing owner-local provider observations if already available.
5. Normalize provider output into ADM-owned evidence entries with `source`, `provider`, `observed_at`, `freshness`, `confidence`, and `uncertainties`.
6. Keep built-in static heuristics as fallback when GitNexus is absent, unhealthy or stale.

## GitNexus integration shape

Treat GitNexus as an optional external provider with two possible activation paths:

- MCP path: import/configure GitNexus as a normal external MCP and call allowed read-only tools through existing Environment MCP authorization.
- CLI path: optionally prepare an allowlisted `gitnexus`/`npx gitnexus` command only when explicitly configured; never run indexing during passive diagnostics.

Preferred first implementation path is MCP, because ADM already has MCP import, activation, health, inventory and capability-report semantics.

## 14-02 scope

Implement only the provider layer and GitNexus integration boundary. Do not yet implement every investigation helper.

Deliverables:

- planning and product contract for provider-backed investigation;
- provider availability/capability facts;
- Gateway-facing read-only provider inspection surface;
- GitNexus MCP/provider adapter skeleton behind optional configuration;
- tests proving absence of GitNexus does not break 14-01 endpoint investigation;
- tests proving provider failures are local and fallback static evidence remains available;
- no indexing, endpoint calls, code execution, verifier runs, process starts or writes during passive inspection.

## Follow-up slices after 14-02

- 14-03: symbol/reference/write tracing using provider results when available and static fallback otherwise.
- 14-04: impact/blast-radius evidence for planned code edits, including upstream/downstream relationships and uncertainties.
- 14-05: data lineage / response field provenance for API and persistence flows.
- 14-06: debug-SQL reverse mapping and test-data metric explanation.
- 14-07: semantic consistency checks using evidence only, not opaque guesses.

## Validation

Required gates:

- `go test -count=1 ./internal/app -run TestInvestigationProvider`
- `go test -count=1 ./internal/gateway -run TestGatewayInvestigationProvider`
- `go test -count=1 ./...`
- `go vet ./...`
- `git diff --check`

Safety checks:

- no private Memory values in provider reports;
- provider errors do not fail ordinary file/search/endpoint investigation;
- passive capability/inspection does not start GitNexus, run indexing, call endpoints, run verifiers, or mutate files;
- provider evidence always includes source/provenance and uncertainty when stale, unavailable or fallback-derived;
- GitNexus remains optional and disabled/unconfigured state is explicit.
