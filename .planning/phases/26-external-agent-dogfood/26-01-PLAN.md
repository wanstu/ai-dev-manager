# Phase 26 Plan — External Agent Dogfood

## Objective

Turn the completed v0.6 Gateway into a real daily-use external-Agent connection before adding speculative v0.7 environment capabilities.

## Scope

This phase may improve Gateway integration/ergonomics only when a real dogfood path proves the gap. It does not add Process/logs/ports/Docker by default.

## Tasks

### 1. Produce a stable dogfood launch flow

Verify the release binary can:

```text
ai-dev-manager gateway up
ai-dev-manager gateway status
```

and report one stable Streamable HTTP endpoint that survives daemon restart.

Document the exact endpoint/tool expectations for connector registration.

### 2. Separate implementation readiness from connector reachability

Classify the target Agent connection:

- local connector/runtime can reach `127.0.0.1` -> use current Gateway directly;
- remote connector/runtime cannot reach loopback -> record this as Gateway exposure/auth integration work.

Do not build remote filesystem/SSH Runtime for this problem.

### 3. Register one real external Agent connection

Using the same connector mechanism that currently exposes another local MCP such as CodexPro when available, register ADM Gateway as a single connector (for example `adm`).

The Agent must see one Gateway tool surface, not one MCP per Environment.

### 4. Complete a small real coding task

Through the external Agent only:

1. `workspace_list`
2. `environment_create`
3. `environment_writer_acquire`
4. routed read/search/git
5. routed edit/write
6. structured exec and/or verifier where appropriate
7. inspect final diff/status
8. leave Environment/branch for human review

The Agent must not require raw worktree path knowledge.

### 5. Capture friction as v0.7 requirements

For each real blocker, classify it as:

- Gateway/Agent API ergonomics;
- connectivity/exposure/auth;
- Environment lifecycle;
- Process/dev server;
- logs;
- ports;
- HTTP verification;
- other evidence-backed capability.

Do not add a capability merely because it was on the old roadmap.

### 6. Verification

Unattended:

```text
go fmt ./...
go test ./...
go test -race ./internal/environment ./internal/gateway ./internal/adapter/mcpgateway ./internal/daemon
go vet ./...
go build -o ai-dev-manager-v0.7-review.exe ./cmd/ai-dev-manager
```

If network behavior changes, also run the fixed-path network acceptance script.

## Exit criteria

- One external Agent has connected to one ADM Gateway and operated an isolated Environment for a real coding task.
- The Agent did not require a new MCP configuration for that Environment.
- Blocking friction is fixed or recorded as evidence-backed requirements for later v0.7 phases.
- No automatic merge/rebase/commit decision was introduced.

## Exit decision

After Phase 26, choose the next v0.7 phase from the first real blocker. Current candidates are Process/dev-server lifecycle, logs, ports/HTTP verification, or Gateway exposure/auth. The order is evidence-driven rather than precommitted.
