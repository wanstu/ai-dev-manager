# Phase 15 Plan 15-01 — Daemon-owned Agent Run Lifecycle

## Objective

实现一个最小但真实的 Agent Run lifecycle vertical slice：daemon 拥有 Run，CLI 通过 loopback Control API 创建/查询/取消，启动 CLI 退出不影响 Run。

## Implementation Steps

1. 新增 `internal/agent`：
   - Run state / status model。
   - crypto-stable `run_` ID。
   - `Executor` contract。
   - production `lifecycle` executor。
   - thread-safe Manager：Start/Get/List/Cancel/StopAll。
   - injected fake executor unit tests covering complete/error/cancel/idempotency/isolation。

2. 新增 daemon Agent Control API：
   - `POST /agent/run`
   - `GET /agent/list`
   - `GET /agent/status?run_id=...`
   - `POST /agent/cancel`
   - client helpers `AgentRun/AgentList/AgentStatus/AgentCancel`。
   - body limits / unknown-field rejection / loopback discovery reuse existing control boundary。

3. 把 Agent Manager 纳入 `daemon.Run` ownership：
   - workspace resolver 复用长期 `controlplane.Service.Registry()`。
   - register handlers only on daemon Control API。
   - shutdown order: Agent StopAll -> Runtime StopAll -> Control Plane StopAll。

4. CLI 增加 `agent`：
   - `agent run [path|workspace-id]`：沿用 workspace target resolution；auto-register path；ensure daemon running；创建 run。
   - `agent list`
   - `agent status <run-id>`
   - `agent cancel <run-id>`
   - human + `--json` output。

5. Process-level acceptance：
   - CLI `agent run` returns while daemon-owned run remains running。
   - independent CLI `agent list/status` sees same run。
   - cancel changes it to cancelled and repeat cancel is stable。
   - two Workspace runs stay isolated。
   - daemon stop/restart does not resurrect old observed runs。

6. Documentation / planning after verification：
   - README add v0.4 Phase 15 lifecycle commands and explicit `lifecycle` executor limitation。
   - ROADMAP/PROJECT/STATE mark ARUN requirements validated only after acceptance passes。

## Exit Decision

Only mark Phase 15 complete when the process-level acceptance proves Run ownership survives the initiating CLI process. Do not claim Agent intelligence in this Phase; the only production executor is explicitly `lifecycle`.
