# Phase 21 Plan 21-01 — Environment State, Single-Writer Guard, and Base Divergence Facts

## Objective

完成 v0.5 Environment Core 的最后一条 vertical slice：让长期存在的 Environment 能安全报告 base/dirty/push/activity facts，并提供持久 single-writer coordination；所有建议保持非指令性。

## Requirements Covered

- ENV-06
- ENV-08
- UX-01

## Implementation Steps

### 1. Add structured Git relation primitive

Extend Native Runtime / Runtime Adapter with `git.relation`:

- input: `left`, `right` refs
- reject empty/option-like unsafe refs before Git invocation
- resolve/compare using structured Git execution and ToolPaths/policy
- output:
  - left commit
  - right commit
  - ahead (left-only count)
  - behind (right-only count)
  - diverged

Use real `git rev-list --left-right --count <left>...<right>` or equivalent without shell interpolation.

Tests:

- equal refs => 0/0
- Environment branch ahead only
- base branch behind Environment only / Environment behind base
- divergence after commits on both branches
- invalid refs rejected

### 2. Persist writer lease in Environment model

Add optional `Writer` to Environment:

- owner
- acquired_at
- last_seen_at

Store clone/round-trip must preserve it and old Environment JSON without Writer remains valid.

Add structured errors:

- `writer_conflict`
- `writer_not_owner`

### 3. Add Manager writer lifecycle

Add:

- `AcquireWriter(envID, owner)`
- `ReleaseWriter(envID, owner, force)`

Rules:

- require non-empty bounded owner identifier
- no writer -> acquire
- same owner -> idempotent renew
- different owner -> conflict
- normal release requires matching owner
- force release clears current lease without requiring owner
- acquire/renew/release updates Environment `last_activity_at`
- writer state survives manager/daemon reconstruction from Store
- stale age never auto-clears writer

Do not build an Agent Manager dependency into Environment Core.

### 4. Make Inspect observational and fact-rich

Change current Inspect behavior so it no longer updates `last_activity_at` merely because it was read.

When managed worktree is valid, inspect gathers through Runtime Adapter:

- git status -> dirty + change count
- git push status -> HEAD/upstream/ahead
- current `base_ref` resolution
- relation between Environment branch and current base
- base_moved relative to recorded base_commit
- writer owner/acquired/last_seen facts
- inactivity duration / 7-day stale fact

If current base_ref cannot be resolved:

- keep inspect successful when Environment worktree itself is healthy
- add `base_ref_unavailable` warning/fact
- do not mutate BaseRef/BaseCommit

### 5. Add restrained hints

Add `Hint` type and `InspectResult.Hints`.

At most one base-sync hint:

- if diverged OR behind >= 10:
  - factual/non-prescriptive text suggesting confirmation whether synchronization is needed
- behind 1..9: facts only

Optional stale warning may be emitted, but it must not prescribe deletion and must not clear writer.

No `required_action`, `next_step`, automatic rebase/merge/push/commit.

### 6. Daemon Control API + CLI writer commands

Add loopback handlers/client calls:

- `POST /environment/writer/acquire`
- `POST /environment/writer/release`

CLI:

```powershell
ai-dev-manager env writer acquire --owner <owner> <env-id>
ai-dev-manager env writer release --owner <owner> <env-id>
ai-dev-manager env writer release --force <env-id>
```

JSON output returns updated Environment/Inspect result; human output shows writer facts compactly.

### 7. Real acceptance

Manager/runtime tests:

- base advances 1 commit -> behind fact, no hint
- base advances >=10 -> one soft hint
- both Environment/base advance -> diverged + one soft hint
- deleted base ref -> warning, inspect otherwise works
- dirty/push facts reflect real Environment state
- Inspect does not update last_activity_at
- 7-day stale fact leaves Environment and writer intact
- writer same-owner renew, second-owner conflict, matching release, force release
- writer survives new Store/Manager instance

Process-level CLI:

1. create Environment
2. writer acquire owner A
3. daemon restart
4. inspect still shows owner A
5. owner B acquire rejected
6. same owner A renew succeeds
7. base branch advances; inspect reports behind without altering branch/worktree
8. force release clears writer

Full:


After all pass:

- mark Phase 21 complete
- move ENV-06 / ENV-08 / UX-01 to Validated with evidence
- mark v0.5 milestone complete in STATE/ROADMAP/PROJECT
- update README
- STOP at milestone boundary before v0.6 Agent MCP Gateway

## Stop Conditions

Stop rather than weakening product boundaries if:

- writer guard requires embedding or owning an AI Agent process
- base facts would require automatic history mutation
- stale handling would require automatic cleanup/release
- Environment inspect would need to trust persisted arbitrary paths instead of managed worktree revalidation

## Exit Decision

Phase 21 and v0.5 complete only when long-lived Environment facts + writer guard are verified end-to-end. Do not auto-advance into v0.6 implementation in the same milestone completion turn.
