# Plan 12-02 — Skill Availability, Support Inventory + Diagnostics

## Objective

Make each Environment-selected Skill visibly usable or unavailable with structured reasons, while preserving the existing bounded artifact/support-file read boundary and avoiding a Skill interpreter.

## User-visible outcome

An Agent can inspect one Skill and know where it came from, whether it is enabled and readable, which support roots are authorized, and why a broken Skill cannot be used.

## Tasks

### 1. Define Environment-specific Skill availability

Return stable states/reasons for at least:

- available;
- disabled;
- unresolved;
- source missing;
- artifact missing;
- artifact unreadable;
- support root missing.

Availability includes Skill/source identity and sanitized source/artifact/support facts.

### 2. Add inspect + bounded files surfaces

Add Agent-facing capability equivalent to:

- `environment_skill_inspect`;
- `environment_skill_files` with bounded inventory;
- existing `environment_skill_read` as authoritative content access.

Inventory/read authorization must remain Environment selection + configured artifact/support-root containment.

### 3. Structure support read failures

Distinguish local support-read problems such as missing file, outside allowed roots, binary/oversize and invalid support root. Do not convert Skill prose into a dependency graph.

### 4. Isolate broken Skills

List/inspect should report per-Skill failures without failing the entire Environment Skill surface. A broken Skill must not block another healthy Skill, MCP or file development.

### 5. Real installed Skill acceptance

Re-run real installed GSD Skill artifact/support-file acceptance after the source model refactor, proving that ADM provides the Skill context while GSD/Agent remains responsible for following it.

### 6. Full Phase 12 evidence

Run refresh/identity/availability/containment tests, real-host acceptance, multi-Environment authorization regression, MCP/file/verifier regression, vet and diff-check. Audit source for absence of orchestration/`.planning` interpretation.

## Done when

Skill availability is a first-class diagnosable ADM capability, real support content remains safely consumable, and ADM still does not interpret or execute Skill instructions.
