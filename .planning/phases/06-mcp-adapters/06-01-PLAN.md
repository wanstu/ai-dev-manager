# Plan 06-01 — MCP host + multi-instance runtime adapter vertical slice

## Objective

用官方 MCP Go SDK 把 Native Runtime 暴露为可连接 MCP server，并验证两个 Workspace 两个隔离 HTTP instance；同时建立协议无关 Runtime Adapter contract 和 CodexPro/DevSpace compatibility 文档。

## Scope Guard

本 Plan 只做：
- official MCP Go SDK dependency in adapter layer
- Runtime Adapter interface + NativeAdapter
- MCP tool registration + in-memory acceptance
- stdio runner
- stateless Streamable HTTP handler
- multi-instance lifecycle manager
- two-workspace HTTP acceptance
- external fake adapter contract test
- compatibility documentation
- milestone verification/transition

不做：公网 tunnel、OAuth、桌面 UI、Docker、Agent/Subagent、修改 codexprov4、完整 DevSpace/CodexPro adapter implementation。

## Task 1 — Add official MCP SDK

Use official Go MCP SDK. Keep imports out of `internal/model`, `internal/config`, `internal/runtime`, `internal/workspace`.

Run dependency resolution with current host Go; if the SDK requires a newer `go` directive than the project's 1.22 baseline, record the compatibility impact explicitly rather than silently raising it.

## Task 2 — Runtime Adapter contract

Create `internal/adapter/runtimeadapter`:
- `Runtime` interface: ID, WorkspaceID, Capabilities, Status, Invoke.
- `NativeAdapter` wrapping `*runtime.Native`.
- typed input decoding helpers with strict validation.
- stable operation names matching runtime capabilities/tool operations.

NativeAdapter must map all currently implemented runtime operations used by MCP tools and return serializable Go structs/maps.

## Task 3 — MCP server adapter

Create `internal/adapter/mcpserver`:
- `New(Runtime) *mcp.Server`
- register `runtime_info` always.
- dynamically register tools based on capabilities.
- tool handlers invoke only the Runtime Adapter interface.
- structured result payloads; sanitize adapter/runtime errors.

Use official SDK generic `mcp.AddTool` APIs.

## Task 4 — In-memory MCP acceptance

Use official `NewInMemoryTransports` client/server pair.

Prove:
- tools list reflects ReadOnly vs Standard capabilities.
- read/search tool calls work against real Native workspace.
- write/exec/git tools are absent when policy does not expose them.
- Standard tool call can edit/read and/or verifier/Git as supported.

## Task 5 — Stdio + HTTP transports

Add:
- `RunStdio(ctx, Runtime)` using `mcp.StdioTransport`.
- `NewHTTPHandler(Runtime)` using stateless Streamable HTTP.

HTTP transport itself does not decide workspace; handler is constructed with one Runtime.

## Task 6 — Lifecycle Manager

Create `internal/host` manager:
- StartHTTP(instanceID, runtimeAdapter, addr)
- Get/List
- Stop

Rules:
- default `127.0.0.1:0`.
- only loopback listen in v0.1.
- one independent listener/server per instance.
- endpoint ends `/mcp`.
- deterministic list.
- duplicate instance id rejected.
- stop idempotent.

## Task 7 — Two Workspace real HTTP acceptance

Use official `StreamableClientTransport`.

Start A/B with separate temp workspace files and independent NativeAdapters.

Prove:
- endpoints differ.
- ListTools/connect works for both.
- A read returns A content, B returns B content.
- A cannot read B through its tool due Runtime containment.
- stop A; B still responds.

## Task 8 — External adapter contract

Create fake Runtime implementing interface without Native.

Prove manager/status can host it, and MCP `runtime_info` works. Add one generic external capability acceptance only if it has a stable MCP tool mapping; otherwise document that unknown capabilities remain visible in runtime_info but are not automatically executable MCP tools.

## Task 9 — Compatibility docs

Create `docs/runtime-adapter-contract.md` documenting:
- contract and capability vocabulary
- Native mapping
- CodexPro mapping table
- DevSpace mapping table
- inheritance/control-plane ownership
- process/transport ownership
- what v0.1 does not yet automate

Do not modify external projects.

## Task 10 — Verification / milestone transition

Run:
- gofmt
- go test ./...
- go vet ./...
- verbose in-memory MCP acceptance
- verbose two-instance HTTP acceptance
- scope search to ensure MCP SDK imports are only adapter/host/test/command transport areas

If all exit criteria pass:
- mark RUN-03 and COMPAT-02..04 appropriately validated.
- record current MCP SDK/protocol/transport decisions.
- mark Phase 6 complete.
- set milestone v0.1 complete in STATE/ROADMAP.
- because auto_advance=true but v0.1 milestone is complete, stop rather than silently entering v0.2 without a roadmap/requirements transition.
