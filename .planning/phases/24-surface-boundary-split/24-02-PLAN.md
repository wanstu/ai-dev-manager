# 24-02 — CLI package extraction

Requirements: ADM-GOAL-001/002, ADM-CORE-003/004/015/017/020, ADM-CLI-001, ADM-MGMT-001, ADM-SURFACE-001, ADM-GW-004, ADM-NONGOAL-001.
New prerequisites: none.

## Objective

Move CLI surface implementation out of `cmd/ai-dev-manager` into a dedicated internal package so the executable entrypoint becomes process bootstrap only, while preserving every current command, flag, JSON/error contract and Admin-MCP/no-fallback boundary.

This plan is structural. It must not add product behavior or reinterpret command semantics.

## Task 1 — Establish an internal CLI surface package

Create a focused package (preferred location `internal/cli`) that owns:

- top-level command routing;
- command/flag parsing and help text;
- JSON stdout / stderr-facing error semantics returned to main;
- MCP import local file/stdin ergonomics;
- normal Admin MCP client construction using the shared Phase-24 target semantics;
- explicit local bootstrap/offline/recovery commands `gateway`, `doctor`, and `state`;
- surface-local narrow backend interfaces used by CLI tests.

Keep Core/application/Gateway/Admin-MCP business behavior outside this package.

## Task 2 — Reduce `cmd/ai-dev-manager` to process bootstrap

The executable package should retain only process-level responsibilities such as:

- loading executable-adjacent `.env`;
- passing `os.Args[1:]` to the CLI runner;
- printing the final error;
- choosing the process exit code;
- OS-specific detached Gateway process mechanics only when import-cycle/dependency direction makes them executable-owned rather than CLI-package-owned.

Do not leave a second copy of command routing in `package main`.

## Task 3 — Preserve CLI behavior exactly

Move/adapt the existing tests so they still prove:

- Workspace/Environment/exec/MCP/Skill/Memory normal management uses Admin MCP;
- `--adm-url` / `ADM_V2_URL` target behavior is unchanged;
- disconnected Admin MCP does not fall back to writable local state;
- Phase-23 MCP import exact-one-source behavior and credential-reference privacy remain intact;
- MCP probe/status/inspect/refresh side-effect distinctions remain intact;
- Skill source update/refresh and availability semantics remain intact;
- Environment context and temporary lifecycle commands remain unchanged;
- help text continues to expose safety boundaries and explicit stable IDs;
- `gateway`/`doctor`/`state` remain the explicit local recovery exceptions.

Prefer moving tests with the owning package where practical, but retain at least one executable-level smoke test proving the thin `main` wiring.

## Task 4 — Enforce dependency direction

Acceptance must prove:

- `internal/cli` may depend on `internal/adminmcp`, shared Gateway target/lifecycle helpers and canonical models/services needed for local recovery;
- `internal/adminmcp`, Core/application and Gateway do not import `internal/cli`;
- Desktop does not import `internal/cli`, and CLI does not import `internal/desktop`;
- no second state/cache/protocol package appears as a result of extraction.

## Acceptance

S11 — `cmd/ai-dev-manager` is a thin executable bootstrap and command implementation lives in one internal CLI surface package.

S12 — all existing CLI commands/flags/help and successful JSON shapes remain behaviorally compatible with the Phase-23 fixed contract.

S13 — normal management still requires Admin MCP; disconnected management never mutates local persisted state.

S14 — local `gateway`/`doctor`/`state` recovery behavior remains explicit and unchanged.

S15 — package dependency direction contains no CLI↔Desktop coupling or Core→surface imports.

S16 — no product model, authorization, persistence, MCP/Skill/Memory/Environment/Runtime semantics or release artifact names change.
