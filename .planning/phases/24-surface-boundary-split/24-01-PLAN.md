# 24-01 — Shared ADM target and management boundary cleanup

Requirements: ADM-GOAL-001/002, ADM-CORE-003/004/015/017/020, ADM-CLI-001, ADM-MGMT-001, ADM-DESKTOP-001, ADM-GW-004, ADM-SURFACE-001, ADM-NONGOAL-001.
New prerequisites: none.

## Objective

Remove duplicated ADM connection-target semantics between CLI and Desktop while preserving the existing Admin-MCP-only normal management authority and all current command/UI behavior.

This is the first structural seam for Phase 24. It must not move product business rules into a surface package or redesign Gateway/Admin MCP protocols.

## Task 1 — Make Gateway target semantics reusable

Likely files:

- `internal/gateway/lifecycle.go`
- `internal/gateway/lifecycle_test.go`
- small new focused target/lifecycle helper file if clearer

Expose/reuse one canonical implementation for:

- validating/normalizing ADM HTTP/HTTPS Base URLs;
- deriving health, Agent MCP and Admin MCP endpoints;
- determining whether a Base URL is eligible for local lifecycle control;
- converting a loopback HTTP root Base URL to a local `host:port` listen address.

Rules:

- existing `/healthz`, `/mcp`, `/admin/mcp` derivation stays unchanged;
- local start/stop/restart remains loopback HTTP only;
- remote HTTPS may be inspected/status-checked but is not locally bootstrapped/stopped;
- base paths remain supported for remote inspection where currently supported, but local lifecycle requires a root Base URL;
- reject userinfo/query/fragment exactly as current normalizers do;
- do not add authentication/TLS policy or a persisted target model.

Prefer extending existing Gateway lifecycle helpers instead of creating a duplicate endpoint package unless dependency direction requires a small neutral helper.

## Task 2 — Migrate CLI connection handling to the shared target semantics

Likely files:

- `cmd/ai-dev-manager/admin_connection.go` initially; later extraction belongs to 24-02
- `cmd/ai-dev-manager/admin_cli_test.go`
- `cmd/ai-dev-manager/main_test.go`

Keep CLI-specific concerns local:

- `--adm-url` parsing;
- `ADM_V2_URL` environment override;
- command-line placement/duplicate-flag errors.

Replace CLI-specific URL/loopback semantic duplication with the shared helper.

Production normal management must still construct/use `*adminmcp.Client` against the canonical Admin MCP endpoint. Admin connection failure must still fail without touching local writable state.

## Task 3 — Migrate Desktop connection/bootstrap handling to the same target semantics

Likely files:

- `internal/desktop/adapter.go`
- `internal/desktop/profiles.go`
- `internal/desktop/connection_test.go`

Desktop profiles remain Desktop presentation state, but validation/endpoint derivation/local-bootstrap eligibility must reuse the same shared target semantics as CLI.

Keep:

- `InspectADMConnection` health inspection;
- `ConnectADM` installing an Admin MCP client only for a running compatible ADM;
- local bootstrap only for eligible loopback HTTP roots;
- no management backend after disconnected/incompatible state;
- no direct frontend Admin MCP calls.

Do not change profile storage format in this plan.

## Task 4 — Strengthen surface production-client contracts

Add focused compile/test assertions that:

- production CLI normal management uses `*adminmcp.Client` and the shared Admin MCP endpoint derivation;
- production Desktop `NewClientAdapter` uses `*adminmcp.Client` only after a compatible connection;
- CLI and Desktop local-target decisions agree for the same representative URLs;
- neither surface silently installs a writable local management backend after connection failure;
- frontend code continues to have no direct `/admin/mcp` network fetch path;
- `internal/adminmcp.Client` remains protocol/tool wrapper code only and does not acquire surface presentation policy.

Surface-local narrow interfaces may remain. Do not create one giant shared interface merely to remove duplicate declarations.

## Acceptance

S01 — CLI and Desktop normalize/derive the same Base URL, health URL, Agent MCP URL and Admin MCP URL for equivalent targets.

S02 — loopback HTTP root targets are local-lifecycle eligible; HTTPS, non-loopback and base-path targets are not locally started/stopped.

S03 — existing custom-port behavior remains valid.

S04 — disconnected/incompatible Admin MCP leaves production Desktop management unavailable and normal CLI fails without writable local state fallback.

S05 — no Workspace/Environment/MCP/Skill/Memory/retention/Runtime product model changes are present in the diff.

S06 — release/user-facing command names are unchanged.
