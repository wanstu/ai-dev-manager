# 24-03 — Desktop adapter separation + integrated closeout

Requirements: ADM-GOAL-001/002, ADM-CORE-003/004/015/017/020, ADM-MGMT-001, ADM-DESKTOP-001, ADM-CLI-001, ADM-SURFACE-001, ADM-GW-004, ADM-NONGOAL-001.
New prerequisites: none.

## Objective

Finish the logical surface split by separating Desktop adapter responsibilities into focused components/files while preserving the Wails/frontend contract, then run cross-surface fixed-head acceptance and close Phase 24.

This plan must not redesign the Desktop UI or introduce Desktop-only authority/persistence.

## Task 1 — Separate Desktop adapter responsibilities

Refactor `internal/desktop` so responsibilities are clearly owned by focused files/components, at minimum separating:

- Wails-facing input/DTO definitions;
- ADM connection inspection/connect/disconnect and local Gateway bootstrap;
- management facade methods;
- Runtime facade methods;
- connection profile persistence/preferences.

The exact file split may follow current dependencies, but exported Wails-bound method names and frontend JSON contracts stay stable.

## Task 2 — Preserve production Admin-MCP-only behavior

Keep `NewClientAdapter()` as the production constructor. A production Desktop connection installs `*adminmcp.Client` only after compatible ADM connection inspection.

`NewAdapter(management.Service)` or equivalent direct local backend remains explicitly test/offline-oriented and must never become an automatic fallback after disconnect, incompatible endpoint or Admin MCP failure.

Desktop frontend remains a client of the Wails-bound adapter. It must not gain direct `/admin/mcp` fetch/call logic.

## Task 3 — Add cross-surface boundary assertions

Add tests/static assertions covering:

- CLI and Desktop both consume shared ADM target semantics from 24-01;
- both normal management paths use `*adminmcp.Client`;
- surface-local backend interfaces stay narrow and are satisfied by the shared production client;
- Desktop and CLI packages do not import each other;
- Core/application/Gateway/Admin-MCP packages do not depend on presentation packages;
- release artifact names remain `adm` and `adm-desktop`;
- no new state file/cache or management protocol was added.

## Task 4 — Integrated regression acceptance

Run acceptance on one fixed implementation head:

- focused `internal/desktop`, `internal/cli`/CLI executable, `internal/adminmcp`, `internal/gateway` tests;
- Phase-23 CLI acceptance and Phase-18/19/22 Desktop/browser helper coverage relevant to changed seams;
- full `go test -count=1 ./...`;
- `go vet ./...`;
- production browser smoke at the existing viewport/scaling matrix;
- CLI release build;
- Wails production Desktop build through `scripts/build-desktop.ps1 -clean -trimpath`;
- `git diff --check`;
- artifact sizes and SHA-256 hashes.

Native GUI click-through remains governed by existing availability semantics. Do not claim Phase-19/22 pending native evidence as PASS without real native GUI-control evidence.

## Acceptance

S21 — Desktop adapter source ownership is visibly separated without changing Wails/frontend behavior.

S22 — production Desktop and normal CLI both remain Admin-MCP clients over the same Core/state authority.

S23 — no surface imports the other and no Core package imports a presentation surface.

S24 — browser/CLI/Desktop/full repository acceptance remains green on one fixed head.

S25 — release/build names remain `adm` and `adm-desktop`; no repository/module split occurs.

S26 — Phase 24 changes are refactor-only from the product perspective: no new business semantics, persistence, auth/TLS, distribution, investigation or orchestration behavior.
