# 17-01 Plan — Conditional Distribution Decision Gate

## Goal

Decide whether Phase 17 needs any implementation after the Phase 15 dogfood fix, and refresh local dogfood artifacts only through existing build paths if that helps daily use.

## Requirements

- Treat Phase 17 as conditional. Do not implement installer/updater/signing/notifications without a concrete dogfood blocker.
- Use existing local build scripts before adding new distribution code.
- Keep Phase 16 closed; do not reopen Desktop feature work or CI/release automation.
- Do not push, tag, publish releases or mutate GitHub Release state.
- Local artifacts must be explicitly identifiable by version string and checksum when built.
- Smoke validation must exercise the current CLI/Gateway code path enough to prove the Phase 15 bounded inspection fix can be used by dogfood builds.

## Non-goals

- No public RC tag or release.
- No installer/updater/signing implementation.
- No Desktop-only state or authorization model.
- No remote Admin MCP enablement.
- No automatic replacement or stopping of the currently connected `pjadm` Gateway from ChatGPT, because that can sever the active tool connection.

## Steps

1. Confirm the repository is clean on `master`.
2. Build a current local CLI artifact with existing Go/build script paths.
3. If the Wails toolchain is available, build the Desktop artifact through `scripts/build-rc.ps1`; if it is unavailable or too slow, record that as a distribution/toolchain limitation rather than adding new code.
4. Start a rebuilt Gateway only on a spare loopback port for validation; do not disrupt the active `pjadm` connection.
5. Validate bounded `environment inspect` output: catalog summary facts should replace unselected disabled Skill/MCP detail facts.
6. Record commands/results in `17-01-VALIDATION.md`.
7. Commit the documentation/validation node if the repository changed.

## Acceptance

- `git status` is clean before starting.
- Current CLI artifact can run `-h`.
- A rebuilt Gateway on a spare port can serve bounded `environment inspect` output.
- `git diff --check` passes for any documentation updates.
- Final repository state is clean after committing documentation updates.
