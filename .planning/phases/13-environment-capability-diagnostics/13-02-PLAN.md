# Plan 13-02 — Runtime Observation Enrichment + Agent-facing Capability Report

## Objective

Enrich the shared capability report with current Gateway-owner observations from completed MCP/Skill/runtime work and expose one Agent-facing capability surface without introducing implicit probes or side effects.

## User-visible outcome

An Agent can ask one Gateway operation what this Environment can currently use and receive desired configuration plus current observed facts, with explicit timestamps/origins and no secret leakage.

## Tasks

### 1. Enrich with Phase 11 MCP runtime observation

For each selected MCP include:

- desired configuration/enable state;
- transport/config readiness;
- current owner observation if present;
- last stage/error;
- tool inventory count/fetch time if observed.

Do not reconnect or call tools merely because capability inspection was requested. If there is no owner observation, report `not_observed`/equivalent honestly.

### 2. Enrich with Phase 12 Skill availability

Reuse the exact Environment-specific Skill availability contract. Do not re-implement source/artifact checks in the capability layer.

### 3. Add process/run owner facts

Report whether the persistent owner supports dev-process and generic async-run lifecycle plus current owned/running counts where useful. These are observations, not persisted desired state.

### 4. Expose one Agent/management surface

Add/upgrade the canonical Environment capability operation so Gateway and CLI consume the same `CapabilityFact` schema. Preserve lightweight Environment list separately; do not dump all diagnostics into every list response.

Optional explicit flags may request richer observation, but default must remain side-effect-free.

### 5. Negative acceptance and dogfood

Exercise one Environment containing simultaneously:

- non-Git root;
- writer lease state;
- enabled/disabled verifier definitions;
- one healthy and one broken MCP;
- one healthy and one broken/unresolved Skill.

Prove one report returns all facts correctly and ordinary operations still behave according to the same reasons.

Test owner restart so stale observations disappear instead of being reported current.

### 6. Full Phase 13 evidence

Run static aggregation tests, owner-enrichment tests, secret/Memory sentinel tests, no-side-effect tests, MCP/Skill/files/process/run/isolation regression, vet and diff-check.

## Done when

Environment capability diagnosis becomes a trustworthy front door to ADM Core availability: one schema, component-local failures, sanitized evidence, current observation when present and no hidden remediation/orchestration behavior.
