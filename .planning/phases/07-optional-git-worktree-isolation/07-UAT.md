# Phase 7 UAT — Optional Git Worktree Isolation

**Result:** passed by deterministic automated evidence on 2026-09-08.

No human-only acceptance item remains for the Phase 7 vertical slice before integration review.

## Covered behavior

1. **Optional capability / non-Git negative acceptance** — a plain non-Git Workspace still creates and uses an ordinary Environment; Git-worktree create fails locally without affecting unrelated Gateway tools.
2. **Two isolated roots** — one real Git Workspace creates two managed worktree Environments with distinct ADM IDs, branches and filesystem roots. A file created in the first root is absent from the second root and the source checkout.
3. **Source checkout preservation** — managed creation does not switch source branch, move source HEAD, or rewrite tracked source content.
4. **ADM-owned authority** — destination and managed branch names are generated by ADM; the Agent-facing create tool accepts no arbitrary worktree path or branch name.
5. **Tamper-before-mutation** — changing the managed branch identity causes routed Runtime construction to fail; the attempted write target is not created. An out-of-Workspace Environment without managed metadata is also rejected.
6. **Safe destroy** — a clean worktree can be destroyed only by its matching writer. Generic `environment_remove` is refused for managed roots.
7. **Dirty/unpublished protection** — dirty work and a locally advanced commit absent from remote-tracking refs both block default destroy. Explicit force removes the worktree root, but the generated branch remains and committed work is still reachable.
8. **Real Agent Gateway path** — managed create/list/destroy succeeds through MCP Streamable HTTP using the current Gateway implementation; the retained branch and unchanged source checkout are verified after destroy.
9. **Regression** — focused packages, full `go test ./...`, `go vet ./...` and `git diff --check` pass.
