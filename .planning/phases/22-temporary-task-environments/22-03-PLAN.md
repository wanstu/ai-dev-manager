# 22-03 — Desktop visibility and Phase 22 integrated closeout

Requirements: 22-01/22-02 requirements plus ADM-MGMT-001 and ADM-DESKTOP-001.
New prerequisites: none.
Execute only after 22-02 acceptance and summary are committed.

## Objective

Make temporary Environment lifecycle visible and safely operable in the existing Desktop Environment management surface through Admin MCP, then close Phase 22 with fixed-head Core/Gateway/browser/Wails acceptance.

This is a bounded lifecycle UX addition, not a Desktop redesign and not a new persistence path.

## Task 1 — Environment retention visibility

Likely files:

- existing Desktop Environment route/render/controller modules
- existing Admin MCP client/adapter wiring only where a missing call wrapper requires it
- browser smoke/helpers

Display for each Environment where available:

- durable vs temporary badge;
- expiry / expired state;
- lifecycle owner;
- optional session/run provenance;
- managed-worktree vs existing-root context when already available from existing data.

Rules:

- unloaded/unknown retention must not be rendered as durable certainty;
- private Memory values remain absent from list/summary rendering;
- provenance strings are informational only and are not rendered as task hierarchy/status;
- no new Desktop state file/cache/authorization model.

## Task 2 — Promote and cleanup UX over Admin MCP

Add bounded actions for temporary Environments:

- refresh lifecycle/status;
- promote to durable;
- cleanup preview;
- cleanup execute only after explicit user confirmation.

UX requirements:

- preview shows eligibility and blocker reasons before destructive execution;
- not-due, wrong-owner, active writer/process/run/verifier/MCP and dirty/unpublished worktree reasons remain visible and do not collapse into generic failure text;
- no force-cleanup UI;
- successful ordinary cleanup removes only the Environment from the UI after refreshed Admin MCP state; it must not imply directory deletion;
- successful managed cleanup explains that the managed worktree root was removed while the branch is retained;
- promotion refreshes the same Environment identity as durable rather than creating/replacing it;
- stale responses from a prior ADM connection/current Environment must be discarded using the existing scope guards.

If Desktop needs an owner value for a temporary lifecycle action, use the persisted lifecycle owner from the selected Environment/status and require explicit confirmation; do not invent or overwrite an owner silently.

## Task 3 — Browser/Wails integrated acceptance

D01 — Environment list/detail clearly distinguishes durable and temporary retention.

D02 — temporary expiry/owner/session/run provenance renders without exposing private Memory values.

D03 — cleanup preview is non-destructive and blocker states are visible.

D04 — promote confirmation calls the Admin MCP lifecycle tool, preserves Environment identity and refreshes durable state.

D05 — cleanup execute requires explicit confirmation and removes only the selected eligible temporary Environment.

D06 — dirty/unpublished/active runtime blockers prevent destructive UI success and remain understandable.

D07 — no force cleanup control is present.

D08 — disconnected/stale Admin MCP behavior follows existing Desktop management rules; no direct writable local-state fallback.

D09 — production browser smoke passes at the established desktop viewport/scaling matrix.

D10 — exact Wails production artifact builds successfully. Native Wails/WebView2 click-through is required only when a real native GUI-control path is available in the session; otherwise record it PENDING under the existing availability semantics and do not claim PASS.
