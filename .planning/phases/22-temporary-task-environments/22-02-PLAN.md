# 22-02 — Agent/Admin temporary Environment workflow

Requirements: 22-01 requirements plus ADM-GW-001/003 and ADM-CORE-022 shared Agent workflow semantics.
New prerequisites: none.
Execute only after 22-01 acceptance and summary are committed.

## Objective

Expose the constrained temporary Environment lifecycle through the shared Agent/Admin Gateway without making generic durable Environment management Agent-writable and without introducing task orchestration.

## Task 1 — Shared Gateway tools

Likely files: `internal/gateway/server.go`, focused Gateway acceptance tests, temporary lifecycle application files only if integration exposes a defect.

Register on both Agent and Admin surfaces:

- `environment_temporary_create`
- `environment_temporary_status`
- `environment_temporary_promote`
- `environment_temporary_cleanup`

Preferred inputs:

Create:

- `workspace_id`
- `name`
- `owner_id`
- `ttl_seconds`
- optional `session_id`
- optional `run_id`
- optional `mode` (`existing_root` default, or `managed_worktree`)
- optional existing-root `root`
- optional managed-worktree `base_ref`

Status:

- `environment_id`

Promote:

- `environment_id`
- `owner_id`

Cleanup:

- `environment_id`
- `owner_id`
- `execute` (false/omitted = preview; true = execute)

Surface contract:

- existing generic `environment_create` stays Admin-only and durable by default;
- existing generic `resource_retention_*` stays Admin management surface;
- temporary create is the narrow Agent-safe create path and cannot choose arbitrary host destinations;
- status/preview are read-only and do not acquire/renew writers;
- promote/cleanup require matching lifecycle owner but do not invent authentication beyond explicit stable owner routing;
- no `force` parameter;
- no implicit Run/process/verifier start, cancel, merge, commit, push or cleanup scheduling.

Tool descriptions must explain that `owner_id/session_id/run_id` are lifecycle provenance, not ADM task orchestration.

## Task 2 — Real Streamable HTTP acceptance

Use a real Gateway owner and real Streamable HTTP clients.

A01 — Agent/Admin parity
- both surfaces expose the four temporary lifecycle tools;
- Agent surface still does not expose generic durable `environment_create`.

A02 — Plain non-Git create/use/restart
- create `existing_root` temporary Environment in a non-Git Workspace;
- verify retention owner/expiry/provenance and ordinary tree/read/write after normal writer acquisition;
- restart Gateway and show temporary retention persists while owner-local runtime observations do not.

A03 — Preview is targeted and read-only
- create two expired temporary Environments;
- preview one by ID and prove neither is removed;
- execute one and prove the other remains.

A04 — Owner authority
- wrong owner cannot promote or cleanup execute;
- matching owner can promote;
- promoted Environment remains the same stable Environment/root/context and becomes durable.

A05 — Managed-worktree optional isolation
- temporary managed-worktree create on a Git Workspace succeeds without changing source checkout;
- cleanup preview/execute uses existing safety and retains branch;
- missing Git/non-Git Workspace fails only managed-worktree mode while existing-root mode remains usable.

A06 — Dirty/unpublished/tampered safety
- dirty/unpublished managed work blocks cleanup;
- managed identity tamper blocks cleanup locally;
- temporary cleanup exposes no force path.

A07 — Active runtime blockers
- active writer, process, generic Run and async verifier Run each block cleanup;
- matching explicit stop/cancel/release or natural terminal state removes only the corresponding active blocker;
- at least one real `vfrun_` blocker is exercised through the Phase-21 lifecycle, not by synthetic map insertion.

A08 — No unrelated capability prerequisite
- no verifier/process/Run/MCP/Skill configured is required for plain temporary Environment create/status;
- no Git required for `existing_root`.

A09 — Provenance is not orchestration
- optional `run_id` is returned/persisted as retention provenance only;
- creating a temporary Environment does not require that run to exist and does not start/cancel/parent any Run.

A10 — Privacy/context
- status/surface output may expose retention owner/session/run metadata but must not dump Environment-private Memory values;
- cleanup/promotion never promote Memory to Global scope.
