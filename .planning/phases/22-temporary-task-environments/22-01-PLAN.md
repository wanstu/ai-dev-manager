# 22-01 — Core temporary Environment lifecycle

Requirements: ADM-GOAL-001/002, ADM-CORE-001/002/003/004/005/010/013/016/017/022, ADM-NONGOAL-001.
New prerequisites: none. Git remains optional and is required only for managed-worktree mode.

## Objective

Create one shared Core lifecycle for atomically creating temporary Environments, inspecting targeted retention state, promoting by matching lifecycle owner, and safely cleaning up exactly one requested Environment while reusing Phase-15 retention and existing managed-worktree/runtime safety.

Do not expose new MCP tools or Desktop UI in this plan.

## Task 1 — Retention model and atomic temporary creation

Likely files:

- `internal/model/retention.go`
- `internal/environment/service.go`
- `internal/isolation/service.go`
- `internal/app/service.go` or a new focused temporary-environment application file
- focused model/environment/isolation/app tests

Implement a narrow request/result model for temporary Environment creation.

Locked inputs/semantics:

- `workspace_id`, `name`, `owner_id`, positive `ttl_seconds` required;
- optional `session_id`, `run_id` provenance;
- mode `existing_root` or `managed_worktree`;
- `existing_root`: optional existing Workspace-contained root, default Workspace root;
- `managed_worktree`: optional `base_ref`, no caller-chosen destination;
- creator surface supplied by application/surface caller, not arbitrary persisted user input;
- add explicit run provenance to retention metadata without giving it execution semantics.

Creation must persist `temporary` retention with `expires_at` in the same state mutation that creates the Environment record. Extend managed-worktree creation with a retention-aware seam so Environment + managed metadata are persisted atomically after Git worktree creation and existing rollback remains authoritative.

Do not reuse/convert an existing durable Environment on duplicate collision. Temporary create must either return a newly created temporary Environment or a clear conflict.

Acceptance T01-T06:

- T01 non-Git `existing_root` create succeeds with temporary retention, owner and expiry;
- T02 optional contained subdirectory succeeds; missing/escaped/outside root fails before state creation;
- T03 missing owner / non-positive TTL / invalid mode fails with no Environment record;
- T04 collision with an existing durable Environment never returns that durable Environment as temporary success;
- T05 managed-worktree temporary create persists managed + temporary Environment identity and keeps source checkout unchanged;
- T06 managed-worktree create failure rolls back partial worktree/branch/Environment state.

## Task 2 — Owner-scoped targeted status/promotion/cleanup

Likely files:

- `internal/app/resource_retention.go`
- `internal/gateway/resource_retention.go` only for reusable owner-evidence helpers, not MCP tools
- new focused temporary lifecycle application/Gateway-owner tests

Add an Environment-targeted lifecycle seam that reuses the canonical retention policy rather than filtering after a global destructive sweep.

Required behavior:

- targeted status/preview evaluates one Environment only;
- cleanup preview never mutates;
- cleanup execute performs a fresh state/runtime safety check and never removes unrelated resources;
- execute requires current retention `temporary`, expiry due and matching lifecycle `owner_id`;
- wrong owner is a local error/blocker and does not mutate;
- promotion requires matching lifecycle owner and changes retention only;
- promotion preserves stable Environment/root/selections/private Memory/managed metadata;
- ordinary cleanup removes only the Environment state/private context and preserves Workspace + directory/files;
- managed cleanup reuses `Isolation.Safety` + `Isolation.Destroy(force=false)` and retains branch;
- no temporary workflow force option.

Refactor generic Phase-15 cleanup helpers only as needed to support a selector/target without changing existing generic Admin semantics.

Acceptance T07-T13:

- T07 not-due temporary Environment previews as blocked/not-due and stays unchanged;
- T08 wrong owner cannot promote or execute cleanup;
- T09 matching-owner promotion yields durable retention and later cleanup refuses it;
- T10 eligible ordinary cleanup removes only Environment state, preserving Workspace/root/files;
- T11 eligible managed cleanup removes the ADM-owned worktree and retains its branch;
- T12 dirty/unpublished/tampered managed worktree blocks temporary cleanup;
- T13 targeted cleanup leaves another simultaneously eligible temporary resource untouched.

Acceptance T14-T18:
