# Phase 17 Plan 17-01 — GSD Planning Loader & Execution Spec

## Objective

实现 `agent run --workflow gsd` 的第一条真实 vertical slice：从 Workspace `.planning` 状态解析当前 phase/plan，读取 PROJECT/STATE/CONTEXT/PLAN，解析 PLAN 内 machine execution spec，通过 Runtime Adapter 执行并运行 verifier/reviewer。

## Implementation Steps

1. 扩展 Agent workflow trace：
   - RunStatus 增加可选 planning source metadata。
   - workflow update 可安全写入 source paths。

2. 新增 GSD planner：
   - runtime `files.read` 读取 `.planning/STATE.md`。
   - 解析 Current Position 的 phase number / plan id。
   - runtime `files.tree` 定位唯一 `NN-*` phase directory。
   - 读取 `.planning/PROJECT.md`、`NN-CONTEXT.md`、`NN-XX-PLAN.md`。
   - 从 PLAN 的 `## Execution Spec` 下解析单个 JSON fenced block。

3. Execution spec validation：
   - schema: `steps[]` + `run_verifiers`。
   - stable non-empty step id；重复 id 拒绝。
   - operation 必须在 Phase 17 GSD allowlist。
   - operation 必须有对应 Runtime capability；`verify.run_many` 映射到 capability `verify.run`。
   - `shell.exec` / worktree / unknown operation 必须在执行前被拒绝。

4. GSD executor/reviewer：
   - 复用 `RuntimeStepExecutor`。
   - `run_verifiers=true` 时自动追加 `verify.run_many`（spec 中不需要手写 verifier step）。
   - reviewer 复用 verifier pass/fail 逻辑；没有 verifier 时只在 `run_verifiers=false` 明确允许 no-verifier review pass。

5. daemon/CLI：
   - 注册 `gsd` executor。
   - `agent run --workflow gsd` 无新增 endpoint。

6. Tests：
   - fixture `.planning` + edit + verifier pass。
   - forbidden shell operation planning error before invoke。
   - missing/ambiguous phase files。
   - missing capability。
   - process-level daemon/CLI status observes planning sources + completed review。

## Exit Decision

17-01 only establishes deterministic, auditable GSD plan execution. It does not automatically rewrite `.planning/STATE.md` after success; that transition is exclusively 17-02.
