# Phase 28 Plan — Agent File Editing Ergonomics

## Objective

Make Agent-facing exact edit tolerate an unambiguous LF ↔ CRLF representation mismatch while preserving the target file's newline style and the existing strict `expected_replacements` safety contract.

## Tasks

### 1. Add narrow newline adaptation to Runtime Edit

Keep current exact matching as the primary path.

Only when exact `old_text` has zero matches:

- detect whether the target file uses a consistent LF or CRLF newline style;
- detect whether `old_text` uses the opposite consistent newline style;
- adapt `old_text` to the file style and count exact matches;
- require the adapted count to equal `expected_replacements`;
- adapt `new_text` to the file style before replacement;
- reject mixed-newline or bare-CR compatibility cases.

Do not normalize spaces, tabs, indentation, Unicode, casing or any other bytes.

### 2. Preserve strict replacement semantics

Regression tests must prove:

- exact match behavior remains unchanged;
- a non-zero exact count that differs from `expected_replacements` still fails immediately;
- fallback count must equal `expected_replacements` exactly;
- failed edits leave the file unchanged;
- no fuzzy/whitespace fallback is introduced.

### 3. Cover Windows newline dogfood cases

Add focused Runtime tests for:

- CRLF file + LF `old_text` / `new_text` → success and CRLF preserved;
- LF file + CRLF `old_text` / `new_text` → success and LF preserved;
- multiple matching CRLF blocks with `expected_replacements=1` → `invalid_edit` and no write;
- mixed newline file → `invalid_edit`;
- indentation/whitespace mismatch → `invalid_edit`.

### 4. Verification

Run through configured Go verifier and focused race gate:

```text
run_verifier(go-test)
go test -race ./internal/runtime ./internal/gateway ./internal/adapter/mcpgateway ./internal/environment
go vet ./...
go build -o ai-dev-manager-v0.7-review.exe ./cmd/ai-dev-manager
```

If the full verifier exposes a Windows transient executable-lock failure, rerun the affected test/package once and then rerun the full verifier before treating it as non-code failure.

## Exit criteria

- Exact edit accepts only clear LF ↔ CRLF representation differences.
- Target file newline style is preserved.
- `expected_replacements` remains strict and atomic failure behavior remains intact.
- Mixed/newline-ambiguous and whitespace-different edits remain rejected.
- Full verifier/race/vet/build gate passes.
