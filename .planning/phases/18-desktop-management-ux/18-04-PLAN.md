Planning baseline: `93a74d9`, 2026-09-11. Detailed plan; implementation/acceptance is NOT STARTED.
Execution gate: delivery and recorded acceptance of 18-01, 18-02 and 18-03. Integrated acceptance remains mandatory even when no additional code fix is needed.

## Outcome

Prove that the finished Desktop works as one management application: current connection/Environment is unambiguous, all existing capability families remain reachable, explicit actions retain their scope, and optional failures remain local. Close Phase 18 only with evidence for the final integrated UI.

This is an acceptance plan with evidence-driven fixes, not an optional polish phase. Do not merge away the acceptance gate when earlier plans already resolved visual issues. A fix task may be unnecessary; the verification/closeout record is still required.

No new features, Core/adapter/schema changes, framework/persistence, native lifecycle redesign, installer/updater/signing, release publication or execution of Phase 19. A newly discovered Core contradiction is recorded in STATE and addressed through an explicitly revised scope before implementation.

Preflight: Git status/log, AGENTS and planning context, all 18-01/02/03 plans/summaries, 18-VALIDATION and this plan. Use the proper writer lease for file/test mutations, local commits on master, no subagents/push/tag/release. Read-only inspection never requires a new product prerequisite.

- Actual integrated frontend assets and the shared real-browser fixture with fake Wails bridge. Never test a copied static mockup as proof of the production UI.

## Completion criteria and blockers

Phase 18 is complete when 18-01/02/03 delivery is recorded, all mandatory D01-D10 cases and applicable A/B/C regressions pass on valid evidence, final code gates pass, the exact Wails artifact has native acceptance, and no unresolved blocking defect remains.

Blocking defects include wrong-target action, private/secret data exposure, authority bypass or global optional-capability prerequisite; lost essential operation/route; broken modal/draft/keyboard navigation preventing normal use; invalid build/bindings; or missing required native/behavior evidence. Fix or explicitly retain Phase 18 as incomplete. Do not “waive” missing required evidence by moving it to backlog.

A minor cosmetic issue may remain only when it does not violate the required behavior/accessibility checks and is recorded with impact/reproduction/follow-up. It must not silently expand this phase into new features. Every pending check includes a concrete next action.
