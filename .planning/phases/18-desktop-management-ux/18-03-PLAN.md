## Page-level design

### MCP

Header shows global definition count and the selected Environment identity. Keep separate add and import actions. Local filters cover existing name/ID/endpoint/executable and existing all/selected/issues/unobserved states; show visible/total counts.

Each row prioritizes name/transport, desired configuration, current-Environment enablement and observed Runtime state. Details disclose endpoint/executable/reference names and health policy without exposing resolved secrets. A configured definition or newly enabled selection is not automatically healthy.

Use distinct labels: “默认用于新 Environment”, “在当前 Environment 启用”, and “从全局删除”. A global deletion confirmation names the definition and global impact; it must not look like a local disable.

Preserve transport-specific editor fields and native dialog drafts. Import flow is paste/select format -> explicit Preview -> candidate errors/warnings/reference requirements -> explicit Apply. Invalidate the preview when payload/format/conflict/default options or connection generation changes. Block Apply on missing/stale/error preview; capture exactly the previewed input/options. A failed apply retains input/error and is never automatically retried.

### Skills

Keep two local subviews: installed Skills and configured Sources, both over existing loaded data. The Skills list supports text/current-selection/state and source filtering. Source records show configured root, discovery/refresh facts and explicit refresh/remove controls. Source changes remain global; Environment switches change only selection/availability view.

Separate source configuration, artifact availability and Environment enablement; report missing/unresolved selected IDs from existing evidence. Preserve unrelated rows during a broken source/availability read. Counts of installed artifacts are not a usable-Skill count.

Removal wording describes the actual source/catalog metadata operation. Do not claim that host artifact files are deleted. No auto-refresh/source scan, automatic enable, support-file read or Skill execution.

### Memory

Use the existing memory route with two labeled scopes: Global and Current Environment. The Environment scope displays the selected Environment name/root/ID from the shared context; it does not introduce an independent hidden selector. No Environment means that scope is unavailable with a selection instruction; global operations remain usable.

Initial view shows counts and “尚未加载内容”. Only explicit Load calls ListGlobalMemory/ListEnvironmentMemory. After loading, list keys/values with the existing edit/delete dialogs and source scope clearly shown. Never include values in the dashboard, badges, diagnostics, navigation hashes or saved preferences.

Move the existing Environment-private Memory list/load controls into the Memory page once. Keep one instance of each editor/control ID. Replace the old detail inline Memory view with an explicit “打开此 Environment 的 Memory” link. That user action closes only the inspected detail, then navigates; it must not discard an editor draft. Capture the target first and require it to match the shared Management Environment.

Critical migration: baseline loadEnvironmentMemory uses selectedEnvironmentID (the detail-modal identity). Bind Memory reads/writes/deletes to an explicit captured tuple of connection generation + scope + Environment ID + entry key. Closing Environment detail must no longer silently invalidate or retarget an active Memory action. Use one shared reset hook and do not preserve a second independent scope model.

Switching scope/Environment/profile clears prior loaded values/consent and rejects late old-scope results. Closing an editor or failed save follows the existing draft/focus contract. Confirmations name the scope and entry key; never replace a pending action's captured target with a newer global selection. After mutation, refresh only the explicitly loaded matching scope plus sanitized counts; unrelated refresh never implicitly loads values.

### System and Environment diagnostics

Gateway page groups saved connection management, endpoint/status facts and local lifecycle actions. Header retains the only active-profile selector. Settings contains existing autostart/tray information; allowlist contains existing executable add/remove/list. Reuse established restrictions and error messages; no new remote connection policy or command runner.

Diagnostics stays in the environments route/detail host, with an “诊断” subview/entry. Keep the top-level route inventory at ten. Opening inspection is an explicit user action. Group returned capability facts by kind and state; show reasons, source/generated/observed time when supplied, unresolved selections and uncertainty. Filtering/expanding loaded facts triggers no probe/tool execution. Missing report fields or static observations remain visibly unknown; there is no fabricated all-green global health.
