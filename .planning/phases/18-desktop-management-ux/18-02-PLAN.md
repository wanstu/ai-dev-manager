## Source and operation map

Baseline `frontend/app.js` contains renderWorkspaces, renderEnvironments, renderEnvironmentDetailFromInspection, renderRuntime, refreshRuntimeContext and runRuntimeAction. `internal/desktop/adapter.go` already exposes all operations below.

| Area | Existing data / bridge operations | Scope and interaction |
|---|---|---|
| Workspace list | GetSnapshot workspaces/environments | Name, stable ID, path and Environment count joined from the same snapshot. Filtering is local; do not inspect every Workspace. |
| Workspace actions | AddWorkspace, RenameWorkspace, RemoveWorkspace | Existing modal/confirmation flow; removal is registration-only and referenced Workspaces remain protected by Core. |
| Environment list/detail | GetSnapshot summaries; InspectEnvironment for explicit detail; existing ListEnvironmentSkills follow-up | Workspace name/ID, root, state, writer observation, selection counts and private Memory count. Do not read private values. |
| Environment actions | CreateEnvironment, RenameEnvironment, RemoveEnvironment | Stable target identity; same root/metadata guards. Existing SetEnvironmentMCP/SetEnvironmentSkill controls remain reachable until 18-03 reorganizes their presentation. |
| Runtime lists | ListVerifiers, ListProcesses, ListRuns | Selected Environment and current Gateway owner only; render independently from other page reads. |
| Runtime explicit actions | RunVerifier, GetProcessLogs, StopProcess, CancelRun | Preserve existing writer and identity arguments. Run output uses the existing ListRuns result; no new GetRunStatus bridge method or start action is required. |

Writer shown in the UI is an observation, not a newly granted authority. Existing Core checks remain final; a stale/wrong/expired writer failure is displayed without acquiring or force-releasing another lease.

## Page and interaction design

| Page | Layout | Concrete behavior |
|---|---|---|
| Workspaces | Heading/add action; local name/ID/path search; readable rows with name, full-path access, Environment count and actions | “查看 Environments” navigates to the environments route with a transient Workspace filter. It does not change the Management Environment or scan the directory. Add/rename errors retain form input; removal wording says registration only. |
| Environments | Heading/create; Workspace filter + local name/ID/root search; rows with current-context marker and concise facts | Distinguish selected Management Environment from list filtering. Keep explicit current-context selection and existing detail opening; row clicks/filter changes do not silently retarget management. Creation can show the chosen Workspace but root validation stays in Core. |
| Environment detail | Existing shared modal with overview facts, current selection controls and clear links to MCP/Skills/Memory | Group identity/root/Workspace, observed writer and capability reasons. Preserve unresolved IDs. Optional availability failure shows a local unavailable reason, not an empty successful list. Detailed capability filtering and final Memory ownership are delivered in 18-03. |
| Runtime | Selected Environment identity + refresh; local Verifiers / Processes / Runs subviews; bounded output area | Switching subview is presentation-only. Keep per-subview loading/empty/error state and existing list cadence; changing tabs adds no reads. Explicit output/log actions identify resource and observation time. |

List filters apply only to loaded data, expose visible/total counts and distinguish “no registered records”, “no filter match” and “not loaded”. Preserve entered filters on refresh; a removed Workspace filter becomes visibly invalid with an explicit reset, not a new Environment selection.

At 1120x760 show concise facts before secondary metadata; at 820x560 stack long rows/actions and let full paths wrap or expand. No new native minimum size. Keep modal/list scroll and keyboard focus restoration from 18-01.

Scope transitions:
- Profile change clears connection-bound lists, filters tied to old IDs, detail, selected output and observation state through the shared 18-01 reset.
- Environment change clears prior private detail/output and in-flight render targets immediately. Accept responses only for the captured connection generation + Environment ID/request generation.
- An open edit/removal confirmation captures its original stable target and profile. Prevent context changes while that modal/action is pending; never retarget the action using a later global selection.
- Removal/rename refreshes authoritative data; do not claim deletion from an optimistic UI change. Preserve Core errors and unrelated rows.
- Store only transient UI filters/subview/output selection. Do not infer liveness from historical rows or persist Runtime output.
