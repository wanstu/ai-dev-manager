# Plan 04-01 — Native Runtime isolation + files + structured exec

## Objective

实现 v0.1 第一个真正执行本地开发动作的 Runtime vertical slice：Native Runtime 可以在 Workspace 内安全读取/搜索/编辑文件，并按 Policy 执行结构化本地命令；路径、权限、tool resolution 都在 Runtime 内强制校验。

## Scope Guard

本 Plan 只做：

- Policy optional fields persistence/resolution
- Runtime capability model
- PathGuard / Workspace containment
- tree/read/write/edit/search
- structured executable + argv command execution
- ReadOnly / WorkspaceWrite / Standard / Full enforcement
- ToolPaths + exec.LookPath resolution
- tests / GSD transition

明确不做：

- raw shell string / automatic `cmd /c` / PowerShell / Bash
- Git status/diff/worktree
- unified apply-patch parser
- Verifier abstraction
- Docker structured API
- MCP Host/server
- Agent/Subagent
- UI

## Task 1 — Extend Policy compatibly

**Files:**
- `internal/model/config.go`
- `internal/config/resolver.go` if clone semantics require it
- `internal/config/store.go`
- tests

**Fields:**

```go
type Policy struct {
    Mode               string
    AllowedExecutables []string
    ToolPaths          map[string]string
}
```

**Rules:**
- existing Policy remains whole-object override: highest non-nil layer wins。
- EffectiveConfig must deep-copy slice/map。
- Store v1 adds optional `allowed_executables` / `tool_paths`。
- old v1 JSON still loads。

**Tests:**
- round-trip fields。
- resolver result does not alias source Policy slice/map。
- project/runtime higher Policy replaces lower Policy as a whole。

## Task 2 — Runtime core + capability model

**Create:**
- `internal/runtime/runtime.go`
- `internal/runtime/runtime_test.go`

**Implement:**
- policy mode constants。
- capability constants/types。
- `Native` construction from `Workspace + EffectiveConfig`。
- immutable snapshot of Workspace/config/policy needed by runtime。
- default missing/empty policy -> read-only。
- invalid mode -> structured `invalid_policy`。
- deterministic `Capabilities()`。

**Capability exposure:**
- all modes expose tree/read/search。
- workspace-write/standard/full expose write/edit。
- standard/full expose shell.exec。

Do not expose capabilities that policy would reject.

## Task 3 — PathGuard and blocked writes

**Create:** `internal/runtime/pathguard.go` + tests.

**Implement:**
- canonical absolute root。
- resolve existing read path with lexical + EvalSymlinks containment。
- resolve write target including nonexistent leaf by validating nearest existing parent。
- `filepath.Rel` containment, never string prefix。
- block direct writes under `.git` and `.ai-dev-manager/runtime`。
- return workspace-relative normalized path for structured results where useful。

**Tests:**
- inside relative/absolute allowed。
- `..` escape denied。
- other workspace absolute denied。
- prefix trick (`workspace2` vs `workspace`) denied。
- blocked paths denied for write。
- symlink escape test when symlink creation is available; skip only on platform permission failure, not on logic failure。

## Task 4 — File operations

**Create:**
- `internal/runtime/files.go`
- `internal/runtime/files_test.go`

**Tree:**
- options maxDepth/maxEntries with hard ceilings。
- stable sort。
- no directory symlink traversal。

**Read:**
- maxBytes required/default + hard ceiling。
- regular files only in first slice。

**Write:**
- deny in read-only。
- exact workspace containment。
- optional createParents bool。
- atomic temp + sync + replace where practical。
- structured result。

**Edit:**
- exact `old -> new`。
- expected replacement count default 1。
- zero/multiple unexpected -> `invalid_edit` and no write。
- reuse guarded atomic write path。

**Tests:**
- mode permission matrix。
- atomic round-trip。
- failed edit leaves file unchanged。
- output result paths stay workspace-relative。

## Task 5 — Text search

**Create:** `internal/runtime/search.go` + tests.

**Implement:**
- literal text search in files under optional subpath。
- bounds: max files, max matches, max bytes/file with hard ceilings。
- skip dirs symlink, skip binary files containing NUL in inspected bytes。
- stable results sorted path then line/match order。
- search is allowed in read-only。

**Do not:**
- add regex engine API yet。
- shell out to `rg`。

## Task 6 — Structured command execution

**Create:** `internal/runtime/exec.go` + tests.

**Policy:**
- read-only/workspace-write -> `execution_denied` before resolution/start。
- standard -> executable basename/name must match AllowedExecutables case-insensitively on Windows semantics。
- full -> no allowlist check。

**Tool resolution:**
1. if ToolPaths contains requested executable name, use configured path after file validation。
2. otherwise `exec.LookPath`。
3. no automatic shell wrapping。

**Command:**
- argv passed directly to `exec.CommandContext`。
- cwd default root; custom cwd guarded。
- default timeout 30s; hard max 10m。
- bounded stdout/stderr capture, with explicit truncation/limit status contract。
- record exit code/duration/timedOut。
- failed non-zero process exit is a CommandResult, not confused with policy/tool lookup failure。

**Windows EXEC-04 test:**
- configure explicit `ToolPaths` to a known host executable available by absolute path。
- prove it runs independent of ordinary lookup path assumptions。
- do not hard-code the developer machine Go path in production tests; locate/inject a test executable path at test setup or use current test binary/helper process pattern。

## Task 7 — Multi-Workspace isolation integration

Create two temp Workspace roots and two Native runtimes with separate configs.

Prove:
- A reads/writes only A。
- B reads/writes only B。
- A cannot target B by absolute or relative escape。
- mutating the caller's EffectiveConfig after `NewNative` does not elevate A permissions。
- Standard A allowlist/tool map does not appear in B。

## Task 8 — Scope review

Search `internal/` to ensure Phase 4 did not add:

- Docker API。
- MCP SDK/server/network hosting。
- Agent abstractions。
- Wails/UI。

Review that Runtime never calls Store/ConfigService or loads disk config layers.


## Definition of Done

- Workspace containment is enforced below tool APIs, including symlink-aware path checks。
- file read/search/write/edit obey policy modes。
- structured command execution obeys policy and tool resolution。
- explicit ToolPaths behavior is tested。
- two runtimes are isolated and immutable from caller mutation。
- tests + vet pass。
- no Git/Docker/MCP Host/Agent/UI scope leak。
