## Proposed contract

App entry points:
- DiscoverWorkspace(ctx, workspaceID, request): resolves Workspace through the existing registry.
- EnvironmentTreeDigest(ctx, environmentID, request): obtains s.Runtime(environmentID) first, preserving managed-root validation.

Request fields: path (relative; empty means root), query (discovery only, literal, at most 200 characters), max_depth, max_entries, max_candidates, max_digest_entries, max_output_bytes.
Zero means default; negative or above-hard-cap values return a clear validation error.

| Budget | Default | Hard cap |
|---|---:|---:|
| depth (root=0) | 4 | 8 |
| entries visited | 2000 | 10000 |
| candidates returned | 50 | 200 |
| digest entries | 100 | 500 |
| serialized report bytes | 65536 | 262144 |

The minimum accepted output budget is 4096 bytes so identity/budget/truncation facts can be represented. Include arrays as empty arrays, not missing success evidence.

Report: Workspace or Environment identity, scope-relative scan path, UTC observed_at, effective budgets, visited counts, candidate list, compact directory digest, truncated, stop_reasons and bounded diagnostics. Report bytes include metadata and diagnostics. Omitted items increment counters; large names and diagnostic lists must not bypass the byte cap. Never silently truncate a candidate root and then use it for creation; omit that candidate with a reason.

Candidate: root relative to authority root, basename, marker paths/kinds, evidence category (marker or directory-only), query-match reason, suggested Environment root. Marker inventory: .git directory/file, go.mod, go.work, package.json, pyproject.toml, Cargo.toml, pom.xml, build.gradle, build.gradle.kts, composer.json, *.sln, *.csproj. Only known marker names/types, no file contents.
- Root with markers is a candidate at ".".
- Nested candidates are retained, not collapsed into their parent.
- Direct child directories without markers may be directory-only candidates, clearly weaker evidence.
- Multiple markers merge by canonical relative directory identity.
- Query ranks exact relative path, exact basename, then literal substring before nonmatches; when query is nonempty return matching candidates only. No match on a partial scan does not prove absence.
- Sort final candidates by query-match class, marker evidence before directory-only, then normalized relative path. Tie-break deterministically.
- Under traversal truncation, the visited subset can depend on filesystem enumeration order; state this uncertainty instead of claiming a complete deterministic index.

Digest entries contain relative path, kind and observed child/marker counts only. Any counts from incomplete traversal are labeled observed, not totals.

## Task 1 — Implement the scanner and bounded result model

Target files: internal/model/workspace_discovery.go; internal/workspace/discovery.go (or a small internal helper if both app entry points need it), focused discovery tests.

- Implement budget validation and paged directory enumeration.
- Prune excluded subtrees and links before descent, enforce physical containment, and stop at limits/cancellation.
- Detect marker metadata, coalesce candidates, compute literal query evidence and compact digest.
- Preserve useful results on child permission/read failures with scope-relative sanitized diagnostics. Root errors are operation failures; cancellation is explicit.
- Bound serialized output including warnings. Do not add state fields, scan cache or compatibility handling.
