## Task 2 — Desktop explicit scan and root handoff

Use the existing Workspace page and shared dialogs; do not create a new top-level route.
- Add an explicit Discover projects action for each stable Workspace row. Opening the dialog shows unloaded state and scan options. Only the explicit scan action calls discovery.
- Render requested scope, effective limits, observed time, candidate paths/marker reasons and compact digest. Truncated/partial results show why and allow an explicit narrower rescan.
- Local filtering of loaded candidates issues no calls. Editing path/query/budgets requires an explicit rescan; never scan on every keystroke.
- Loading, empty, no match, partial and failure are distinct. Preserve report scope; reject late responses on Workspace/profile/dialog-generation changes. Disable duplicate scans while pending.
- Candidate Use root pre-fills the existing Create Environment form with stable Workspace ID and exact relative root, without submitting it or changing current Management Environment.
- Creation is explicit and revalidates the root through existing Core. Candidates that disappeared or became links cannot bypass creation containment.
- If matching Environments already exist, display their explicit identities and offer existing inspection/navigation, without assuming one is the intended target.
- Environment detail gets an explicit directory-summary action using environment_tree_digest; no automatic scan on inspection or diagnostics navigation.
- No global MCP probe or Skill availability result is recomputed/retargeted by discovery or Environment handoff.
