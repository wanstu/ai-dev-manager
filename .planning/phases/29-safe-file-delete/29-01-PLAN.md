# Phase 29 Plan — Safe File Delete

## Objective

Add a first-class Agent-facing `delete` mutation for one file while preserving Runtime path safety, write policy and Environment single-writer semantics.

## Tasks

### 1. Native Runtime capability

Add `files.delete` to writable Runtime modes and implement a narrow delete operation:

- require write-capable policy;
- validate the target through existing workspace/write containment rules;
- reject workspace root and directories;
- keep `.git/**` and `.ai-dev-manager/runtime/**` blocked;
- return `not_found` for missing targets;
- remove exactly one file/symlink entry;
- return a small structured result containing the deleted relative path.

### 2. Runtime Adapter and Environment routing

Add protocol-neutral `files.delete` operation mapping.

Environment mutation routing must:

- recognize `files.delete` as an allowed mutation;
- require the `files.delete` capability;
- preserve the existing writer-owner check and success-only activity renewal.

### 3. Gateway tool

Expose one `delete` tool with:

```text
environment_id
writer_owner
path
```

Use the same routed mutation output envelope and stable domain-error behavior as `write`/`edit`.

### 4. Regression coverage

Tests must cover:

- writable Runtime deletes one regular file;
- read-only delete fails;
- missing path → `not_found`;
- directory deletion rejected;
- blocked metadata path rejected;
- outside-workspace/symlink escape remains rejected;
- Gateway surface includes `delete` and routes it through writer-guarded Environment mutation;
- wrong writer does not invoke Runtime.

### 5. Verification and real dogfood

Run:

```text
run_verifier(go-test)
go test -race ./internal/runtime ./internal/environment ./internal/adapter/mcpgateway ./internal/gateway
go vet ./...
go build -o ai-dev-manager-v0.7-review.exe ./cmd/ai-dev-manager
git diff --check
```

Then restart ADM using the already-approved `@pj` handoff, switch back to `@pjadm`, and validate:

```text
write(temp file)
delete(temp file)
read(temp file) -> not_found
run_verifier(go-test) -> PASS
```

The post-restart dogfood must not use `exec` or `git clean` to remove the test file.

## Exit criteria

- Agent can delete one file without shell/Git workaround.
- Delete cannot recursively remove directories or metadata paths.
- Writer/policy/path guardrails are unchanged and enforced below MCP.
- Full verification and real post-restart `@pjadm` dogfood pass.

## Completion — 2026-09-05

Implemented `files.delete` across Native Runtime, Runtime Adapter, Environment mutation routing and the Agent Gateway. Writable modes advertise `files.delete`; read-only does not.
