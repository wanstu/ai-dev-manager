# Plan 07-01 — Control Plane Composition & Introspection

## Objective

实现 Phase 7 的单一 vertical slice：从真实持久化 Workspace ID 进入 Control Plane，得到 EffectiveConfig 与 Native Runtime，启动 MCP endpoint，并以结构化 snapshot 解释运行时状态和配置来源。

## Task 1 — Control Plane Service composition root

Create:

```text
internal/controlplane/service.go
```

Implement:

- `Service` 持有 Store、Registry、ConfigService、Host Manager。
- `New(root string)`：root 为空时使用 `config.DefaultRoot()`，显式 root 用于测试/CLI。
- 暴露 `Registry()` 供 Phase 8 CLI 复用 Workspace CRUD；不复制 Registry API。
- `Resolve(workspaceID, runtimeOverride)` 返回 Workspace + EffectiveConfig。
- `BuildRuntime(...)`：空 RuntimeID / `native` → `runtime.NewNative` → `runtimeadapter.NewNative`；其他 RuntimeID 返回结构化 unsupported runtime error。
- Runtime adapter ID 必须稳定地包含 Workspace identity，避免多个 workspace 混淆。

Verification:

- table test：default/native runtime selection 成功。
- unknown runtime selection 返回可判定 error kind。

## Task 2 — Safe introspection snapshot

Create or extend:

```text
internal/controlplane/service.go
internal/controlplane/service_test.go
```

Implement deterministic snapshot structs with JSON tags:

- Workspace identity/path/profile/runtime selection。
- policy mode + source。
- sorted runtime capabilities。
- sorted MCP summaries：id/enabled/source/enabled_source/transport/command/url；不包含 `Env` values，也不解析 EnvRefs values。
- sorted Skill summaries。
- sorted Verifier summaries。

Rules:

- `Enabled == nil` 在 EffectiveConfig summary 中按 resolver 当前语义保留“未显式启用”的状态，不在 introspection 层重新定义继承规则。
- 输出顺序稳定，便于 CLI JSON 和测试。

Verification:

- Global/Profile/Project 混合配置的 Source/EnabledSource 正确。
- snapshot 中不存在 secret env value。

## Task 3 — MCP lifecycle through Control Plane

Implement wrappers:

```text
StartMCP(ctx/options)
GetMCP
ListMCP
StopMCP
StopAll
```

Start path must be:

```text
workspace id
→ Resolve
→ BuildRuntime
→ NativeAdapter
→ host.Manager.StartHTTP
```

Do not let the caller pass a prebuilt Native runtime for the normal workspace path.

Verification:

- official MCP client connects to Control Plane-started endpoint and reads a real temp workspace file。
- two workspaces can start simultaneously through one Service。
- workspace A cannot read workspace B path。
- stop A does not break B。
