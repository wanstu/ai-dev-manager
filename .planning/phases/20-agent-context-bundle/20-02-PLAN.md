# 20-02 — Gateway context surface and capability guidance

Requirements: 20-01 requirements plus Agent-facing Gateway delivery under ADM-GW-001/003.
New prerequisites: none.
Non-goals: implicit current Environment state, dynamic data in MCP initialize instructions, CLI/Desktop context pages, Memory/Skill content auto-injection, automatic MCP connection/probe, task orchestration.
Execute only after 20-01 acceptance is recorded and DTO names are calibrated against committed Core code.

## Task 1 — Gateway-owner enrichment without side effects

Add an owner-level context bundle path that starts from the 20-01 Core bundle and enriches only information the current Gateway owner already knows.

- Reuse `runtimeOwner.CapabilityReport` semantics for owner-observed MCP/process/run facts instead of inventing parallel health logic.
- For each Environment-enabled MCP, include bounded observed tool **names** only when an existing owner observation contains inventory. Preserve observation time/state and omitted-tool counts.
- If no observation exists, report `not_observed`; do not connect, initialize, ping, refresh inventory or schedule reconnect simply because a context bundle was requested.
- Never expose tool schemas if doing so threatens compactness; Phase 20 needs discovery guidance, not a second full MCP `tools/list` dump.
- Run/process owner counts or lifecycle availability may inform guidance, but context generation must not start/cancel/stop anything.
- Re-run final byte compaction after owner enrichment so owner data cannot bypass the bundle limit.

## Task 2 — Agent/Admin MCP tool and static server instructions

Register a read-only `environment_context_bundle` tool on the shared Agent/Admin capability surface. Input: stable `environment_id` plus the bounded request fields from 20-01. It requires no writer.

The tool description must state that it is an explicit bounded context snapshot and does not probe/execute optional capabilities.

Use MCP `ServerOptions.Instructions` for **static Agent usage guidance only**. The instruction contract should be concise and non-project-specific:

- ADM routes by stable Workspace/Environment IDs; there is no implicit current project.
- after an Environment is chosen, clients may call `environment_context_bundle` once to obtain compact root/tree/capability/MCP/Skill/verifier/run guidance;
- unavailable optional capabilities are local facts, not a reason to reject ordinary file development;
- mutations still require matching writer authority;
- the bundle does not itself execute a task or grant new authority.

Do not inject Environment paths, catalog entries, Memory or runtime observations during initialize. Do not add per-session Environment selection state.

Admin remains a superset of Agent tools; no new mutation is introduced. Normal CLI context output is deferred to Phase 23 rather than adding another Phase-20 surface.
