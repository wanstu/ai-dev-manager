## Proposed Core contract

Add a shared model for an Environment context request/report. Calibrate final type names against repository conventions, but keep one application entry point conceptually equivalent to:

`EnvironmentContextBundle(ctx, environmentID, request) (model.EnvironmentContextBundle, error)`

Request fields: `path`, `max_depth`, `max_entries`, `max_digest_entries`, `max_output_bytes`. `path` is Environment-relative and applies only to the digest portion. Zero means default; invalid negatives and above-hard-cap values fail clearly.

Use the Phase-20 defaults/hard caps from `20-CONTEXT.md`. The bundle additionally exposes deterministic internal section limits and omitted counters so output truncation is truthful.

Suggested report sections:

- `environment`: stable Environment/Workspace identity, names, authorized root and writer-presence/expiry facts without private Memory values;
- `tree`: the existing Environment tree-digest evidence or a lossless compact projection preserving scan path, observed time, limits, visited entries, coverage, stop reasons and omissions;
- `capabilities`: compact canonical available facts plus bounded unavailable/degraded/disabled/unconfigured issues with reason/message/requires-writer/source/freshness;
- `mcps`: Environment-enabled MCP IDs/names and safe desired/static state only; no endpoints, headers, env values or connection secrets;
- `skills`: Environment-enabled Skill IDs/names, availability state/reason, relative artifact/support counts; no `SKILL.md` content;
- `verifiers`: ID/name/kind/enabled plus availability/reason; no execution and no need to reproduce command args;
- `guidance`: factual ADM operation guidance derived from actual availability, such as read/search operations, writer-required mutation, verifier IDs, generic Run lifecycle availability and explicit Skill/MCP access operations. Guidance must not be a task plan;
- `omissions` / `coverage`: counts and reasons for section compaction.

Do not duplicate an independent capability truth model. Summaries must be derived from existing Environment inspection/capability/Skill/verifier data and Phase-19 digest authority.

## Task 1 — Model and deterministic compaction

Target: `internal/model/environment_context.go` (or calibrated equivalent) plus focused model/helpers tests.

- Define JSON-friendly request/report DTOs with explicit empty-array success evidence.
- Implement request validation/defaults and deterministic section/output compaction.
- Bound the final serialized report. Never shorten stable IDs/roots/tool names into ambiguous values; omit whole lower-priority items and increment omission counts.
- Preserve timestamps/freshness and distinguish static, observed and not-observed evidence.
- Keep DTOs free of persisted state/schema changes.

## Task 2 — Application composition through existing authority

Target: `internal/app/environment_context.go` and tests.

- Resolve the Environment by stable ID and reuse existing Workspace/managed-root authority.
- Obtain the bounded Environment tree digest through the existing Phase-19 entry point rather than implementing a second scanner.
- Reuse the static capability report and existing Environment/selection/Skill/verifier APIs.
- Prefer one shared snapshot/composition path where practical; do not add hidden caching or background refresh.
- Return safe MCP/Skill summaries only. Do not return MCP endpoint/header/env reference values, Skill file contents or Memory values.
- Root/managed-root failure is fatal. Optional capability absence remains represented locally in the bundle instead of failing unrelated sections.
- Bundle generation requires no writer and must leave persisted state byte-for-byte unchanged.

## Task 3 — Core acceptance and summary

C01 Plain non-Git Environment with no Git/verifier/MCP/Skill/executable returns identity + bounded tree + file capability/guidance without writer.

C02 Populated fixture returns enabled MCP/Skill/verifier summaries with stable IDs and useful states; output contains no MCP secret-bearing values, Skill sentinel contents, Global Memory values or Environment-private Memory values.

C03 Unknown Environment, parent/absolute digest path, missing root and tampered managed worktree fail through existing authority.

C04 Tree depth/entry/digest/output limits and final bundle byte cap are exercised independently; output reports omissions/partial coverage rather than pretending completeness.

C05 Large MCP/Skill/verifier/capability fixtures hit deterministic section caps and remain within output bytes; stable IDs and roots are never text-truncated into unusable identities.

C06 Optional capability failures remain local. No Git/verifier/MCP/Skill/executable is a prerequisite for a valid bundle.

C07 Persisted state bytes are unchanged; no writer is acquired; no process/run/verifier/MCP/Skill operation is executed or refreshed.

C08 Repeated small static bundles have stable ordering after removing observation/generated timestamps.
