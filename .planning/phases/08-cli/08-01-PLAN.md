# Plan 08-01 — CLI & Foreground MCP Serve

## Objective

交付第一个可执行 `ai-dev-manager`，通过薄 CLI 调用 Phase 7 Control Plane 完成 Workspace 注册/查看、runtime inspect 与 foreground MCP serve。

## Task 1 — Testable CLI entrypoint

Create:

```text
cmd/ai-dev-manager/main.go
cmd/ai-dev-manager/main_test.go
```

Implement:

- `main` 只建立 signal-aware context、调用 `run`、输出错误并设置 exit code。
- `run(ctx,args,stdout,stderr)` 解析 global flags 与命令。
- global flags：`--config-root`、`--json`。
- 无命令/未知命令返回明确 usage/error，不 panic。
- CLI 只依赖 `internal/controlplane` 与 `internal/workspace` public API；不自己 resolve config / new Native。

## Task 2 — Workspace and inspect commands

Implement:

```text
workspace add --path ... [--profile ...] [--runtime ...]
workspace list
workspace show <id>
inspect --workspace <id>
```

Output:

- JSON mode使用稳定 snake_case DTO/snapshot。
- text mode保持简洁。
- `inspect` 直接序列化 Control Plane Snapshot。

Verification:

- 同一 temp config root 中 add → list → show。
- inspect 返回 `runtime_id=native` 与 capabilities。
- duplicate/unknown workspace 错误来自 Registry/Control Plane，不被 CLI 吞掉。

## Task 3 — Foreground MCP serve

Implement:

```text
serve --workspace <id> [--listen ...] [--instance ...]
```

Behavior:

1. 调用 `Service.StartMCP`。
2. 立即输出 endpoint/instance metadata。
3. 阻塞直到 context cancellation。
4. 使用短 timeout context 调用 `StopMCP`。
5. 非 loopback listen 继续由 host policy 拒绝。

Verification:

- test 中用 cancellable context 启动 `run(... serve ...)`。
- 读取 endpoint 后用官方 MCP client 连接并 `read` real workspace file。
- cancel 后 run 正常结束。
