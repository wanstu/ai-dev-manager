# Phase 20 Plan 20-01 — Dirty Change Transfer and Safe Destruction

## Objective

实现 `env create --include-changes` 与 `env destroy --force` 的真实闭环，同时把普通 destroy 从 Phase 19 的 `HEAD == base_commit` 保守判断升级为 dirty + upstream/push safety 判断。

## Requirements Covered

- ENV-03
- ENV-07
- UX-01（destructive facts/warnings 继续保持非指令性）

## Implementation Steps

### 1. Add Runtime Git change-set primitives

Extend Native Runtime with structured change transfer types/operations:

- `GitChangeSet`
  - staged patch
  - unstaged patch
  - untracked regular files
- staged patch from `git diff --cached --binary --full-index --no-ext-diff --`
- unstaged patch from `git diff --binary --full-index --no-ext-diff --`
- untracked paths derived from structured `GitStatus()` entries (`??` only), so ignored files are naturally excluded.
- untracked reads go through Runtime containment; reject non-regular/symlink-unsafe content and enforce bounded snapshot size.

Preserve partially-staged semantics rather than copying only final file bytes.

### 2. Add safe patch stdin/apply boundary

Internal `runtime.Command` gains bounded stdin support used by structured Git helpers. Do not automatically add a new public MCP shell-exec stdin field in this Phase.

Add structured apply behavior:

1. staged patch -> `git apply --index ... -`
2. unstaged patch -> `git apply ... -`
3. untracked files -> Native safe write

Any failure returns structured error and leaves the target Environment/worktree for inspection.

Runtime Adapter adds internal protocol-neutral ops for export/apply change set so Environment Manager never reaches into Native or `os/exec`.

### 3. Extend Environment create with IncludeChanges

Add `IncludeChanges bool` to Environment CreateRequest, daemon request, and CLI `--include-changes`.

Create flow:

1. if include_changes, export source change set before worktree creation.
2. record source dirty facts/counts.
3. create Environment at the same resolved committed base used by Phase 19.
4. build validated derived Runtime.
5. apply exported changes.
6. re-read target git status and return `changes_included` fact/warning-free success metadata.
7. if materialization fails, persist Environment state=error, retain managed worktree/branch, and return failure.

Default create remains unchanged and continues returning `changes_not_included` when source is dirty.

### 4. Add structured push safety status

Native Runtime adds a structured Git push-safety query for the current checkout:

- HEAD commit
- upstream presence/ref
- commits ahead of upstream

Do not implement push.

Destroy safety:

- dirty -> unsafe_destroy
- HEAD == BaseCommit -> commit-safe even with no upstream
- HEAD != BaseCommit and no upstream -> unsafe_destroy/unpushed
- HEAD != BaseCommit and upstream ahead count > 0 -> unsafe_destroy/unpushed
- HEAD != BaseCommit and upstream ahead count == 0 -> commit-safe

Return facts in manager/HTTP error context where practical without prescribing push/commit as a next action.

### 5. Add force managed-worktree removal

Extend Runtime worktree remove with optional `force` while preserving existing callers:

- default remove behavior unchanged.
- `force=true` uses Git worktree force removal on the same derived managed path only.
- branch is never deleted.

Environment `Destroy(ctx, id, force)`:

- normal path enforces dirty/push safety.
- force bypasses dirty/unpushed guards but still revalidates managed worktree identity.
- if actual worktree is missing, force may remove only the persistent Environment record; it must not act on stored arbitrary path.

Daemon/CLI add `--force`.

### 6. Tests

Runtime real Git tests:

- partially staged file survives export/apply with staged/unstaged split.
- binary tracked patch applies correctly.
- untracked regular file copied.
- `.gitignore`-ignored file not exported/copied.
- change-set size/path safety enforced.
- push status: no upstream, ahead local, pushed/zero-ahead.
- forced worktree removal remains managed-root bound.

Environment tests:

- include_changes true transfers staged + unstaged + untracked.
- default false remains Phase19 behavior.
- materialization error leaves error Environment record.
- normal destroy rejects dirty/unpushed.
- pushed+clean normal destroy succeeds.
- force destroys dirty/unpushed but branch remains.
- force on missing worktree removes only stale registry record.

Process-level CLI acceptance:

- create with `--include-changes` from dirty dev checkout.
- inspect after independent CLI invocation / daemon restart.
- `env destroy --force` behavior.

## Stop Conditions

Stop rather than weakening safety if:

- preserving staged/unstaged semantics would require bypassing Runtime policy.
- ignored/untracked enumeration cannot be made deterministic through Git status.
- force destroy would require trusting the persisted worktree path instead of managed inventory.
- push safety cannot distinguish no-upstream from actual command/runtime failure.

## Exit Decision

Phase 20 completes only when dirty change transfer and safe/force destruction pass real Git and cross-process acceptance. Do not implement stale/writer/base-divergence or MCP Gateway in this Phase.
