# Phase 24 Plan 24-01 — Environment-routed Read and Git Tools

## Objective

Add six read-only Agent-facing tools to the stable Gateway MCP and route every call through a revalidated Environment derived Runtime without requiring writer ownership or mutating activity.

## Requirements Covered

- GW-04
- GW-06 continuation

## Implementation Steps

### 1. Add Environment Manager read invoke boundary

Add a protocol-neutral method such as:

```text
InvokeRead(ctx, environmentID, operation, input)
```

Rules:

- trim/validate environment_id.
- only allow: `files.tree`, `files.read`, `search.text`, `git.status`, `git.diff`, `git.branch`.
- load Environment from Store.
- call existing `validatedRuntimes` every invocation.
- use the returned derived Runtime only; never persist/cache Runtime or trust stored path.
- map each operation to its required capability and return `ErrCapabilityMissing` before Invoke when absent.
- wrap Runtime invoke failures as `ErrRuntime` with stable Environment error semantics.
- do not touch LastActivityAt or writer lease.

Add tests with fake Runtime builders proving each invocation rebuilds/revalidates and unsupported mutation operations are rejected.

### 2. Extend Gateway service

Expose one narrow read method forwarding to Environment Manager, e.g.:

```text
InvokeEnvironmentRead(ctx, envID, operation, input)
```

Keep MCP SDK types out of core service.

DomainError should preserve Environment error code. For capability missing, facts may include required capability where available, but no required_action/next_step.

### 3. Add typed MCP inputs/tools

Reuse Direct MCP parameter semantics while adding required `environment_id`:

- `tree`
- `read`
- `search`
- `git_status`
- `git_diff`
- `git_branch`

Outputs use a generic typed envelope:

```text
ok
result?
error?
```

Tool failures use Phase 23 pattern: `isError=true` plus structured error envelope.

Do not add write/edit/exec/verifier tools in this phase.

Update `gateway_info.tools/capabilities` to include routed read categories.

### 4. In-memory adapter tests

Verify:

- total Gateway tool surface is 14 tools.
- all read calls forward environment_id and correct Runtime operation/input.
- invalid environment_id/query/path input remains structured tool error where appropriate.
- runtime/domain errors keep stable code.
- no writer_owner field is accepted/required on read tools.

### 5. Real Environment routing tests

Use real Git + Environment Manager to create two Environments from one Workspace and change each independently.

Through Gateway MCP verify:

- `read` sees only selected Environment file content.
- `search` returns only selected Environment matches.
- `git_status/git_diff/git_branch` reflect selected Environment branch/worktree.
- another Environment and main checkout remain isolated.
- an Environment with active writer can still be read without owner argument.
- LastActivityAt before/after read calls is unchanged.

### 6. Revalidation acceptance

After Environment creation, simulate invalid managed state using existing test hooks/real worktree removal or persisted mismatch fixture.

A subsequent Gateway read must fail with `worktree_missing`/`worktree_mismatch`; it must not operate on the old persisted path.

### 7. Daemon restart MCP acceptance

Extend process-level Gateway test:

- create Environment;
- call routed read;
- daemon stop/start;
- endpoint unchanged;
- same `environment_id` routed read works again.

### 8. Verification and closeout

Targeted:

```text
go test ./internal/environment ./internal/gateway ./internal/adapter/mcpgateway ./internal/daemon ./cmd/ai-dev-manager
```

Direct MCP regression:

```text
go test ./internal/adapter/mcpserver ./internal/host
```

Full:

```text
go fmt ./...
go test ./...
go vet ./...
go build -o ai-dev-manager-phase24.exe ./cmd/ai-dev-manager
```

After pass:

- GW-04 -> Validated.
- README documents routed read usage.
- Phase 24 complete.
- auto-advance Phase 25 Writer-safe Mutation & Verification.

## Stop Conditions

Stop rather than weaken the contract if:

- routed read would require trusting stored worktree paths directly;
- unified Gateway tools would require breaking Direct MCP;
- read tools would need writer acquisition or activity mutation;
- capability handling would require per-Environment MCP reconfiguration.

## Exit Decision

Phase 24 completes only when one Gateway MCP can safely read multiple isolated Environments by `environment_id`, with real isolation and managed-worktree revalidation proven through MCP acceptance.
