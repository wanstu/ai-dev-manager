# Plan 11-03 — MCP JSON / JSONC Import Adapters

## Objective

Let users migrate existing MCP configuration into ADM without manually recreating every server, while keeping one canonical ADM MCPDefinition model and preserving ADM safety/authorization semantics.

## User-visible outcome

A user can paste/import one JSON/JSONC payload from OpenCode, WorkBuddy/CodeBuddy, Codex plugin MCP JSON, Claude Code or MCPHub, preview exactly what ADM understood, then import one selected server or a whole selected batch. Conflicts, unsupported fields and credential problems are visible before any write.

## Tasks

### 1. Build a source-neutral import pipeline

Create an application-owned importer boundary with two explicit operations:

- preview: parse source -> detect/select adapter -> normalize candidates -> validate -> return sanitized preview;
- apply: reparse/revalidate the same source, select one/many candidates and atomically persist them through the canonical MCP service.

Conceptual inputs:

```text
format: auto | opencode | workbuddy | codex-plugin | claude-code | mcphub
json_or_jsonc
single_name / selected_names
conflict_policy: error | skip | update_by_name
options: default_include, optional source-scope selector; no target-Environment option in Phase 11
```

Do not persist import-source blobs or introduce source-specific fields into `MCPDefinition`.

### 2. Support OpenCode JSON/JSONC

Recognize current OpenCode V2 `mcp.servers`.

Normalize:

- local `type: local` + command array -> stdio executable/args;
- optional `cwd`/`environment` -> supported ADM stdio config/ref fields;
- remote `type: remote` + `url` -> Streamable HTTP;
- headers/env reference syntax such as `{env:NAME}` -> ADM references/templates;
- `disabled` and source timeout are preview facts/mappings only and must not silently rewrite ADM Environment membership.

If older/alternate OpenCode shapes are deliberately supported, they must have committed fixtures and explicit adapter branches rather than permissive guessing.

### 3. Support WorkBuddy / CodeBuddy JSON

Recognize `mcpServers` entries used by current WorkBuddy/CodeBuddy MCP configuration.

Normalize standard fields:

- stdio `command`, `args`, `env`, optional cwd;
- remote `http` / `streamableHttp` aliases + `url`, `headers`;
- timeout when it maps cleanly to ADM runtime config.

Source-specific extensions such as runtime/package-registry/install metadata or `x-workbuddy` presentation metadata are surfaced as preview warnings unless ADM has an equivalent runtime field. Never silently emulate installer/package-manager behavior.

### 4. Support Codex plugin MCP JSON

Phase 11 JSON import covers Codex plugin `.mcp.json`, not native `~/.codex/config.toml`.

Recognize:

- `{ "mcpServers": { ... } }` wrapper;
- supported direct top-level server map form.

Normalize stdio command/args/env/cwd and Streamable HTTP URL/headers into canonical ADM definitions. Deprecated/unsupported SSE entries are reported as unsupported instead of silently converted.

### 5. Support Claude Code JSON

Recognize:

- project/plugin `.mcp.json` `mcpServers` wrapper;
- full Claude user/local JSON containing `projects.<path>.mcpServers`, requiring an explicit project/scope selector when multiple project maps exist.

Normalize stdio and HTTP/`streamable-http` aliases. Preserve `${VAR}` and supported `${VAR:-default}` expressions as references/templates without resolving them during preview.

Do not import Claude approval/permission state as ADM Environment authorization.

### 6. Support MCPHub data-source JSON

Recognize both known MCPHub families:

- standard `mcpServers` wrapper;
- hub-oriented `servers` map (including version/enabled/description/command/args/env/timeout-style records).

Normalize only connection/runtime fields ADM actually supports. Hub-only routing/filtering/required/TLS/aggregation semantics are warnings or unsupported fields unless separately approved as ADM capabilities.

Do not treat one third-party MCPHub implementation's extensions as a universal schema.

### 7. Make auto-detection deterministic

`format=auto` may select an adapter only when the source shape is unambiguous.

If multiple adapters match and would normalize differently, return `ambiguous_format` with candidate adapter names. Never guess silently.

A generic `mcpServers` wrapper may share a standard parser internally, but the selected source adapter remains visible in preview so source-specific aliases/warnings are deterministic.

### 8. Define safe conflict + atomic apply behavior

Preview each candidate with:

- source server name;
- detected format;
- normalized transport/config summary;
- health-policy result/defaults;
- warnings;
- blocking validation errors;
- existing ADM name/ID conflict facts.

Apply rules:

- default conflict policy is `error`;
- `skip` is explicit;
- `update_by_name` is explicit and preserves existing ADM MCP ID + Environment selections while replacing desired config and dropping affected owner session/inventory/health observation;
- duplicate names inside the selected source are blocking;
- selected batch apply is one atomic desired-state update: one invalid selected candidate means none of the selected candidates persist;
- single import is the same pipeline with exactly one selected candidate.

### 9. Convert credentials into references during import

- raw input JSON/JSONC is ephemeral and is never included in normal logs/status;
- recognized source env-reference syntaxes normalize into reference/template values without resolution during preview;
- resolved secret values are never returned by preview;
- literal values in credential-bearing headers/env keys are converted into generated secret/environment-reference requirements instead of being persisted as literals;
- preview returns only the generated reference name, candidate name and field path; it never echoes the credential value;
- apply persists the generated reference/template only. The caller must provision that reference before MCP activation can become healthy;
- conversion does not introduce a new ADM plaintext secret store in Phase 11;
- errors identify field path/reason without echoing the credential value.

### 10. Agent/CLI/management surfaces

Expose importer through the shared application management boundary so CLI, MCP management and later Desktop can reuse identical parsing/validation.

Minimum Agent/management operations:

- `mcp_import_preview`;
- `mcp_import_apply`.

Phase 11 import writes only global MCP definitions. It does not enable imported MCPs in any existing Environment and exposes no target-Environment argument. Imported definitions default `default_include=false` unless the ADM import request explicitly sets the global default-include option.

These operations accept content, not arbitrary host filesystem paths. A later human UI may load a local file and pass its content through the same boundary.

### 11. Deterministic fixture acceptance

Commit representative JSON/JSONC fixtures for every supported source shape and test:

- single import;
- batch import;
- auto detection;
- explicit format;
- transport aliases;
- environment refs/templates;
- unsupported extension warnings;
- conflict error/skip/update behavior;
- selected-batch atomicity;
- credential conversion into generated secret/environment-reference requirements without literal persistence;
- import never modifies existing Environment selections in Phase 11;
- imported definitions activate through the real Phase 11 HTTP/stdio runtime after apply once any generated secret references are provisioned.

## Done when

Users can migrate common MCP JSON/JSONC configurations into ADM safely and predictably, without hand-copying each definition, without external schemas infecting ADM Core, and without silent overwrite, authorization changes or credential leakage.
