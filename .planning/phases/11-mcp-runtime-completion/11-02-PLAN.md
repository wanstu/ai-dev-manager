# Plan 11-02 — MCP Health Monitor, Automatic Reconnect, Inventory + Diagnostics

## Objective

Make the actual MCP runtime observable and self-recovering without unsafe retries: protocol Ping health checks, configurable automatic reconnect, real tool inventory, explicit refresh and actionable failure stages under the persistent Gateway owner.

## User-visible outcome

A user can configure how often ADM checks an enabled MCP, how long a probe may take, whether ADM automatically reconnects an unhealthy server, and how often reconnect is attempted. Status shows current health/recovery facts and real tool inventory. A broken server can recover without keeping the launching Agent client connected.

## Tasks

### 1. Define one owner-local MCP runtime observation model

Record per `(environment_id, mcp_id)`:

- desired enable/config identity references;
- observed state and transport;
- failure stage: activation/connect/ping/discover/list_tools/call/reconnect;
- structured `error_kind` and sanitized message;
- `last_check_at`, `last_healthy_at`, `last_success_at`;
- `consecutive_failures` and `next_reconnect_at`;
- whether a probe/reconnect is currently in flight;
- bounded public tool inventory + `inventory_fetched_at`.

Never persist session/process/health/timestamps/failure counters/tool inventory as desired ADM state.

### 2. Use protocol Ping as the health probe

The official Go MCP SDK exposes `ClientSession.Ping`; use that for normal periodic liveness checks rather than repeatedly calling `tools/list` as a heartbeat.

For each enabled MCP with `health_policy.health_check_enabled=true` and a live session:

- schedule Ping using `health_policy.check_interval_seconds`;
- bound each probe by `health_policy.probe_timeout_seconds`;
- success updates health timestamps and clears consecutive failure state;
- timeout/protocol/transport failure marks the observation unhealthy and drops the unusable session;
- health monitoring stops immediately when the MCP/Environment is disabled or removed.

Tests should use controllable/fake timing where possible rather than sleeping for production-scale intervals.

### 3. Implement configurable background reconnect

When an enabled MCP is unhealthy or has no live session:

- `auto_reconnect` defaults to `false`;
- if `auto_reconnect=false`, keep the structured unhealthy state until an explicit safe refresh/list/inspect path reconnects;
- if `auto_reconnect=true`, retry activation/connection on the user-configured fixed `reconnect_interval_seconds`;
- do not add exponential backoff, adaptive retry or hidden jitter policy in Phase 11;
- only one reconnect may be in flight per Environment/MCP;
- configuration change, disable/remove or Environment drop invalidates pending recovery generation so stale work cannot resurrect old capability;
- successful reconnect marks healthy and refreshes public tool inventory;
- failure updates sanitized stage/error/failure count/next retry time.

Background reconnect owns only connection/session recovery. It never invokes an arbitrary MCP tool.

### 4. Add explicit inspect + refresh semantics

Agent-facing operations:

- `environment_mcp_inspect` — sanitized desired config + health policy + current owner observation;
- `environment_mcp_refresh` — explicitly drop stale observation/session, activate again, Ping/discover and fetch real inventory;
- existing `environment_mcp_tools` remains a real consumption surface and may populate inventory when absent/stale.

Environment disable/remove must immediately close runtime state, cancel monitor/recovery work and invalidate inventory.

### 5. Keep tool-call retry semantics safe

- safe Ping/discovery/list/refresh operations may establish a fresh connection;
- any connection/list/ping error clears stale healthy state;
- tool-call transport/protocol failure invalidates the session;
- **never automatically replay the same tool call**, before or after background reconnect;
- a later caller may explicitly invoke the tool again after inspecting/recovering runtime.

Add an invocation-count helper MCP so hidden replay is machine-detectable.

### 6. Improve structured diagnostics

Use stable error kinds/stages for at least:

- disabled/not enabled;
- unresolved definition;
- invalid/incomplete configuration;
- missing secret reference;
- unsupported transport/auth;
- executable not allowlisted / stdio launch failure;
- ping timeout / ping protocol failure;
- connection refused/failed;
- auth failure;
- protocol/discovery failure;
- tool-list failure;
- tool-call failure;
- reconnect failure;
- owner closed.

Messages must be useful without embedding resolved headers/env secrets.

### 7. Restart/reconciliation proof

Through a real Gateway process:

- start with enabled HTTP and/or stdio MCP plus a non-default health policy;
- observe real health and tool inventory;
- force the helper unhealthy and prove periodic Ping detects it;
- prove automatic reconnect occurs on the configured interval when enabled;
- stop Gateway and prove owned child/session cleanup;
- restart and prove desired config/health policy survives but old health timestamps/inventory do not masquerade as current;
- the new owner resumes monitoring/reconciliation from desired state.

### 8. Full Phase 11 runtime evidence

Run focused health-policy tests, race owner monitor/reconnect/drop paths, real HTTP/stdio recovery acceptance, regression MCP/Skill/files/verifier/process/generic Run, vet and diff-check. Record any long aggregate transport timeout separately from product failure.

## Done when

An enabled MCP has an explicit observable health/recovery lifecycle: ADM detects unhealthy sessions with protocol Ping, can reconnect at a user-configured interval without an attached Agent client, exposes current evidence, and never converts recovery into unsafe automatic tool replay.
