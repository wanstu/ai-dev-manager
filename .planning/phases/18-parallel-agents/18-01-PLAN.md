# Phase 18 Plan 18-01 — Parallel Verify Worktree Lanes

## Objective

实现 `agent run --workflow parallel-verify`：parent Run 接收 2–8 个 lane，每个 lane 通过现有 managed Git worktree API 创建隔离 checkout，基于同一 EffectiveConfig 构建 derived Runtime，并发执行 verify workflow，最后聚合 review 并按配置清理/保留 worktree。

## Implementation Steps

1. Agent request/input contract：
   - RunSpec 增加 `Input map[string]any`。
   - Manager 新增 StartRequest，同时保持 `Start` / `StartWithExecutor` 兼容 wrapper。
   - daemon `/agent/run` 接收 optional input。

2. CLI：
   - `agent run --workflow parallel-verify --lane name:branch --lane name:branch [--keep-worktrees] [target]`。
   - 只有 parallel-verify 接受 lane flags；其他 workflow 传 lane 时拒绝。
   - lane 数 2–8，name/branch unique。

3. Derived Runtime：
   - Control Plane 新增 derived runtime builder：复用 base Workspace EffectiveConfig，但 root/path 和 observed identity 指向 managed worktree。
   - 不写 persistent Workspace Registry。

4. Parallel executor：
   - base runtime capability 必须包含 `git.worktree`。
   - sequential create managed worktrees。
   - 从 structured create result 读取 path，禁止用户传 derived path。
   - 为每 lane 构建 derived runtime。
   - goroutine 并发执行 VerifyPlanner → RuntimeStepExecutor → VerifyReviewer。
   - lane 状态/plan/steps/review/error 持续写入 parent Run status。

5. Aggregate reviewer：
   - all lane pass → parent review pass。
   - any lane review fail → parent review fail，parent Run completed。
   - create/build/invoke infrastructure error → parent Run error。

6. Cleanup：
   - default after aggregate 调用 base runtime `git.worktree.remove` sequentially。
   - `keep_worktrees=true` 时保留。
   - cleanup failure → parent Run error，并保留 audit state。
   - branch 不删除。

7. Tests：
   - input validation / executor selection compatibility。
   - fake runtime 验证 sequential create + concurrent lane execution + aggregate pass/fail。
   - real Git temp repo：2 worktrees roots distinct，main HEAD/branch unchanged，default cleanup removes worktrees。
   - CLI process-level acceptance observes parent + lane audit data。
