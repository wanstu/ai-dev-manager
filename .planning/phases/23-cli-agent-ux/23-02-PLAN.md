## Task 2 — Temporary Environment lifecycle CLI

Likely files:

- `internal/adminmcp/client.go`
- `cmd/ai-dev-manager/management_backend.go`
- `cmd/ai-dev-manager/main.go`
- CLI/Admin-MCP tests

Add the missing Admin MCP create wrapper and expose the Phase-22 lifecycle directly:

### Create

`adm environment temporary create --workspace-id WS_ID --name NAME --owner-id OWNER --ttl-seconds N [--session-id ID] [--run-id ID] [--mode existing_root|managed_worktree] [--root PATH] [--base-ref REF]`

- owner is explicit and non-empty;
- TTL is explicit and positive;
- mode defaults to `existing_root` through the existing server semantics;
- `root` is meaningful only for existing-root mode;
- `base-ref` is meaningful only for managed-worktree mode;
- no caller-supplied destination/branch/creator-surface field;
- `session_id` / `run_id` remain provenance only and do not require a live Run.

### Status

`adm environment temporary status --environment-id ENV_ID`

Read-only; no lifecycle owner input, writer acquisition or mutation.

### Promote

`adm environment temporary promote --environment-id ENV_ID --owner-id OWNER`

Matching owner only; retention-only mutation preserving stable Environment identity/root/context.

### Cleanup

`adm environment temporary cleanup --environment-id ENV_ID --owner-id OWNER [--execute]`

- omitted `--execute` = preview;
- `--execute` = explicit destructive execution after the server's fresh safety recheck;
- no force flag or interactive hidden override;
- output is the canonical targeted cleanup result including blocker reasons;
- ordinary existing-root cleanup messaging/help must not imply directory deletion;
- managed-worktree help must state root removal retains the generated branch.

The CLI does not invent/default lifecycle owner, task identity or creator surface. Because it calls the existing Admin MCP tool, creator-surface authority remains the Admin MCP surface.
