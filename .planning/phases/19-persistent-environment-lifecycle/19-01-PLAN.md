# Phase 19 Plan 19-01 — Persistent Environment Registry and Lifecycle

## Objective

实现第一条真实 Environment Core vertical slice：同一 registered Workspace 可以创建多个长期存在的 managed-worktree Environment，通过 daemon Control API / CLI 跨进程 list/inspect/destroy；daemon restart 后 Registry 仍存在，并且 derived Runtime 只从重新验证过的 managed worktree 构建。

本 Plan 不实现 MCP Gateway、`include_changes=true`、force destroy、Process/Docker/Debug 或 UI。

## Requirements Covered

Primary:

- ENV-01
- ENV-02
- ENV-04
- ENV-05（Phase 19 保证不做自动 integration）
- ENV-09
- UX-01（先建立 facts/warnings 基础返回边界）

Partial foundation:

- ENV-03：只报告 dirty changes_not_included；materialization 留给 Phase 20。
- ENV-07：先实现 conservative destroy；force/unpushed 精确语义留给 Phase 20。

## Implementation Steps

### 1. Extend structured Git worktree creation for explicit base

Update `internal/runtime/git.go` and Runtime Adapter without breaking Phase 18 callers:

- Add a structured ref resolver that resolves `HEAD` or user-supplied branch/tag/commit to an immutable commit hash through existing Native Git execution.
- Reject empty / option-like unsafe ref input before invocation; pass resolved hash to worktree creation rather than carrying arbitrary rev text into later operations.
- Extend worktree create with optional resolved start commit; old two-argument behavior remains HEAD-compatible for existing parallel-verify.
- Replace the Phase 18 branch `safeIdentifier` limitation for branch names with Git-valid branch validation that permits `/` such as `adm/coupon-share`, while still rejecting invalid/option-injection inputs.
- Keep worktree `name` as the existing strict managed-path identifier; Environment will use its `env_` ID as `worktree_name`.
- Runtime Adapter `git.worktree.create` accepts an optional `start_point`/resolved commit and preserves old input compatibility.

Tests:

- default HEAD worktree creation still passes existing tests.
- explicit older commit / alternate branch creates worktree at the resolved commit.
- `adm/foo` branch succeeds.
- existing branch fails clearly and no substitute branch is created.
- invalid branch/ref input never escapes structured Git execution.

### 2. Add persistent Environment domain/store

Create `internal/environment` with no HTTP/CLI dependency.

Minimum types:

- `Environment`
- `State` = creating / ready / error
- `Fact`, `Warning`, optional structured `EnvironmentError`
- `CreateRequest`
- `InspectResult`

Environment fields follow 19-CONTEXT: stable `env_` ID, Workspace ID, display name, branch, base ref, base commit, worktree name/path, state, timestamps and optional error.

Add a versioned JSON Store:

- independent file/schema from Workspace Registry and desired-runtimes.
- config-root scoped.
- atomic temp-write + sync + rename, matching existing project persistence safety conventions.
- deterministic ordering by Environment ID for stable output/tests.
- malformed/unsupported version returns structured load failure; never silently treats corruption as empty.
- generated IDs use crypto/rand with `env_` prefix.

Tests:

- create/load/update/remove round trip.
- multiple Environments survive reload with stable IDs.
- corrupt/unsupported state is rejected.
- failed atomic replacement does not silently overwrite a valid prior file where testable.

### 3. Add Environment Manager over existing Control Plane/Runtime contracts

Create an Environment Manager that receives explicit dependencies rather than reaching into CLI/HTTP globals:

- base Workspace/runtime resolver/builder.
- derived Runtime builder.
- persistent Store.
- clock/ID generator hooks where useful for deterministic tests.

`Create` flow:

1. resolve the registered base Workspace and base Runtime.
2. require Git/worktree capability.
3. determine base:
   - no explicit base -> current checkout HEAD, and record current branch when available as `base_ref`; detached HEAD falls back to the immutable HEAD commit representation.
   - explicit base -> resolve it to `base_commit`; retain requested text as `base_ref` for diagnostics.
4. inspect base Git status and attach facts/warning when dirty; Phase 19 still does not copy these changes.
5. normalize display name and derive default branch `adm/<sanitized-name>` unless an explicit branch was supplied.
6. detect/propagate `branch_exists`; do not suffix the branch automatically.
7. create and persist a `creating` record before Git side effects.
8. create managed worktree named by `env_` ID from resolved base commit.
9. re-list base Runtime worktrees and verify the returned Environment path corresponds to that managed worktree; do not trust persisted/requested path alone.
10. build a derived Runtime rooted at the validated worktree and check ready status/capabilities.
11. persist ready state/path/timestamps.
12. on failure persist error state with structured facts; do not pretend the Environment was never created and do not perform speculative branch/history cleanup.

Name collision semantics:

- display name is not identity; Store may suffix a duplicate display name if needed for presentation.
- branch collision is authoritative and returns `branch_exists`.
- Environment ID never changes.

### 4. Implement safe Environment inspection / runtime revalidation

`List` returns persisted identities/state without requiring all Runtime objects to stay alive.

`Inspect(envID)`:

- loads persisted record.
- resolves base Workspace/runtime again.
- obtains actual `git worktree list` from base Runtime.
- verifies the Environment's expected worktree name/path against the actual managed inventory.
- if missing/mismatched, returns a structured error/fact and keeps Registry record intact.
- if valid, lazily builds derived Runtime using the validated actual path.
- returns safe facts such as base checkout dirty-at-create warning, branch, base ref/commit, worktree availability and capabilities.

Security invariant:

> A path read from `environments.json` is never sufficient authorization to build a derived Runtime. Actual base Runtime managed-worktree inventory must confirm it first.

Add tests for registry tampering/path mismatch and manually missing worktree.

### 5. Implement conservative Phase 19 destroy

`Destroy(envID)` is intentionally stricter than the final Phase 20 contract:

1. revalidate actual managed worktree.
2. build the derived Runtime.
3. require `git.status` empty.
4. resolve Environment `HEAD` and require no new commit relative to recorded `base_commit` (Phase 19 can conservatively require equality).
5. remove worktree through base Runtime `git.worktree.remove` using managed `worktree_name`.
6. remove Environment Registry record only after successful worktree removal.
7. never delete the Git branch.

If dirty/new commits exist, return `unsafe_destroy` with facts; no `--force` yet. Phase 20 will replace the simple equality guard with dirty/unpushed-aware policy and explicit force.

### 6. Daemon ownership and loopback Control API

Wire one Environment Manager into the existing daemon alongside RuntimeOwner and Agent Manager.

Add loopback-only handlers/client contract, for example:

- `POST /environment/create`
- `GET /environment/list`
- `GET /environment/status?id=<env-id>` or equivalent existing handler style
- `POST /environment/destroy`

Rules:

- no new externally exposed listener.
- daemon restart reloads Environment Store; Runtime objects are rebuilt lazily/observationally.
- daemon shutdown does not delete Environment/worktree persistent state.
- corrupt Environment Store prevents false healthy Environment behavior and returns a clear control error.

### 7. CLI thin client

Add top-level `env` command:

```powershell
ai-dev-manager env create --name coupon-share [--base master] [--branch hotfix/coupon] [path|workspace-id]
ai-dev-manager env list
ai-dev-manager env inspect <env-id>
ai-dev-manager env destroy <env-id>
```

Rules:

- create target defaults to current directory and reuses the same path/Workspace resolution behavior as `up` / `agent run`.
- create ensures daemon is running.
- `--name` is required in Phase 19; no LLM/task-name generation in ADM.
- human output highlights env ID, project/workspace, branch, base commit, worktree state and dirty-not-included warning.
- `--json` returns structured fields/facts/warnings without prescriptive `next_step` / `required_action` fields.

### 8. Real acceptance: same Project, two persistent isolated Environments

Process-level acceptance must use a real temporary Git repo and independent CLI invocations:

1. create baseline commit on a `dev` branch.
2. add an uncommitted main-checkout file/change.
3. `env create --name task-a` with default base.
4. `env create --name task-b --base dev` (or another explicit ref/commit fixture).
5. verify two stable `env_` IDs, distinct branches/worktree paths.
6. verify main checkout dirty content was not copied into either Environment and main HEAD/branch is unchanged.
7. modify Environment A through its derived Runtime; verify B and main do not see it.
8. stop/start daemon; independent `env list/inspect` still sees both Environments and validates real worktrees.
9. manually remove one worktree in a controlled fixture; inspect reports missing/error without deleting Registry record.
10. conservative destroy rejects an Environment with new work; clean Environment destroy removes worktree/Registry but leaves branch.

After implementation and all gates pass:

- mark Phase 19 complete in STATE/ROADMAP.
- move fully satisfied ENV requirements from Active to Validated with evidence.
- create Phase 20 executable planning only after Phase 19 behavior is proven.
- update README with `env create/list/inspect/destroy` only after real CLI acceptance.

## Stop Conditions

Stop rather than guessing if any of these become true:

- Existing Git worktree safety contract cannot support explicit base without opening arbitrary path/shell behavior.
- Correct recovery would require persisting Runtime/listener/process objects rather than reconstructing them.
- Environment Registry path cannot be independently revalidated against actual managed Git worktrees.
- A requested behavior would require automatic merge/rebase/commit decisions.

## Exit Decision

Phase 19 is complete only when persistent Environment identity + real managed worktree + restart-safe inspect + conservative destroy work end-to-end. Do not advance into `include_changes`, MCP Gateway, Process/Docker/Debug or UI inside this Plan.
